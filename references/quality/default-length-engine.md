# Default Length Engine（默认字数引擎）

> **版本**：v1.0（v3.7 新增）
> **类型**：字数预算系统（不是硬 KPI，是生成预算）
> **核心原则**：Natural Completion > Target Word Count. 一篇文案应该在"刚好讲够"的地方结束。
> **统计口径**：纯正文 / 纯口播字数，不包含标题、hashtags、画面建议、内部 QA、Product Role、IP Asset 等 metadata。

---

## 一、字数是什么

**字数 = 信息预算，不是成品长度。**

字数负责控制：
- 这一篇打算讲多少信息
- 展开到什么程度
- 信息密度如何

字数不负责：
- 必须写满多少字
- 达到目标字数才算完成
- 越长越好 / 越短越好

**一篇文案应该在"刚好讲够"的地方结束。**

---

## 二、统计口径

只统计：
- **纯正文字数**（小红书 / 公众号）
- **纯口播字数**（抖音 / 视频号）

**不统计**：
- 标题
- Hashtags / 标签
- 画面建议 / 镜头脚本
- 内部 QA 结果
- Product Role / IP Asset / Primary Proof
- Route / Angle Score / Source Type
- Fact Ledger / 模式判定 / Creative Driver
- 任何内部 metadata

## 五、Complexity 调整系数

生成前判断任务复杂度，根据 Complexity 调整最终字数预算。

| Complexity | 系数 | 适用场景 |
|---|---|---|
| SIMPLE | ×0.7–0.85 | 单一事实 / 简单演示 / 一句话能说清的角度 / 纯发现型内容 |
| STANDARD | ×0.9–1.1 | 标准角度 / 一个核心判断 + 2-3 个支撑点 / 常规种草卖货 |
| COMPLEX | ×1.1–1.3 | 多层论证 / 框架型内容 / 多个维度比较 / 认知型长文 / 需要充分展开的观点 |

### 判断方法

问自己三个问题：
1. 这个角度几句话能说清，还是需要展开？
2. 核心命题需要几个支撑点？
3. 当前 Purpose 完成需要多少信息量？

综合判断 Complexity，然后调整预算。

## 六、IP 模式的字数

IP 模式**不设固定额外字数**。

只有当：
- 人物判断确实需要展开
- 方法确实需要讲清楚
- 价值观确实需要说明白

时，允许比普通模式自然增加约 **10%–25%**。

### 禁止

为了体现 IP 而补：
- 自我介绍
- 个人经历
- "我认为""我觉得"的重复表达
- 无意义的人格标签

**IP 感来自判断的质量，不是字数的堆砌。**

---

## 七、Stop Condition（停止条件）

如果同时满足以下条件，则**立即停止**，不要为了凑字数继续写：

1. **Core Proposition 已经表达完整**
   - 核心命题讲清楚了
   - 没有遗漏关键信息
   - 用户能理解核心意思

2. **Core Proof 已经足够**
   - 核心证据已经呈现
   - 证据足以支撑核心命题
   - 再加证据只会重复

3. **当前 Purpose 已经完成**
   - Content：内容价值已交付
   - Seed：偏好已经建立
   - Sell：购买决定的关键信息都有了

4. **下一段只会产生：**
   - 重复
   - 额外卖点
   - 总结
   - 金句
   - 强行升华
   - 免责声明补丁

**满足以上条件 → 立即停止。**

**Natural Completion > Target Word Count.**

---

## 八、反方向：没达到 Target 也要写完

反之：

**即使达到 Target，如果当前 Purpose 尚未完成，继续写到任务充分完成。**

字数预算是上限参考，不是任务完成的标准。

任务完成的标准是：
- Content：用户获得了内容价值
- Seed：用户建立了偏好
- Sell：用户可以完成购买决定

不是：字数到了。

## 九、平台额外规则

### 抖音 Douyin

画面承担的信息也算内容。

画面已经证明的事实，口播不重复。

因此抖音**允许低于字数 Target**。

**视觉证明 = 内容的一部分，不浪费字数重复说。**

### 小红书 Xiaohongshu

长度由 **Decision Value（决策价值）** 决定。

不是越长越容易收藏。

决策价值够了，短也没关系。
决策价值不够，写再长也没用。

### 公众号 Official Account

长度由 **Thesis Complexity（论题复杂度）** 决定。

不为了"深度感"扩写。

论题简单就写短，论题复杂就写长。
复杂不复杂看论题本身，不看平台标签。

### 视频号 Channels

允许比抖音多一层判断解释。

但禁止为了"信任感"自动写成长篇人生感悟。

信任来自判断的质量和边界，不是话多。

## 十、常见错误

### 错误 1：凑字数

为了达到 Target 而补：
- 重复解释
- 多余卖点
- 金句总结
- 免责声明
- 背景介绍
- "总的来说"

**为什么错**：字数是预算，不是任务。

### 错误 2：统一字数模板

不管什么角度、什么 Purpose，都写差不多长。

**为什么错**：不同角度需要的信息量不同。

### 错误 3：越长越有深度（公众号病）

为了显得有深度，把简单的观点扩写成长文。

**为什么错**：深度来自观点的质量，不是字数。

### 错误 4：越短越精炼（抖音病）

为了短而短，把必要的信息删掉。

**为什么错**：短是因为画面承担了信息，不是因为要"精炼"。

### 错误 5：IP 模式 = 更多字

认为 IP 内容就应该更啰嗦。

**为什么错**：IP 感来自判断的质量，不是字数。

---

## 十一、字数自检清单

生成后问自己：

1. 核心命题讲清楚了吗？
2. 核心证据够了吗？
3. 当前 Purpose 完成了吗？
4. 如果继续写，会增加新价值还是只会重复？
5. 有没有为了凑字数加了多余的东西？
6. 有没有为了"深度感"扩写了不需要的内容？
7. 画面已经证明的东西，口播/正文有没有重复说？
8. 如果删掉最后一段，会不会影响理解？
9. 如果是 IP 内容，增加的字数是因为判断需要展开，还是为了"有人味"？
10. 这篇是不是在"刚好讲够"的地方结束的？

---

## 十二、最终原则

> **字数负责控制信息预算，不是控制成品长度。**
> **一篇文案应该在"刚好讲够"的地方结束。**
> **Natural Completion > Target Word Count.**
> **画面证明了的，口播不重复。**
> **决策价值够了，小红书就不用再写了。**
> **论题简单，公众号就不用写长。**
> **信任来自判断的质量，不是话多。**
> **IP 感来自判断的质量，不是字数的堆砌。**
