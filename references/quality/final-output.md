# 成品真人感与平台原生层（references/final-output.md）

> **Source of Truth：成品真人感与平台原生层 + Final Output Contract。** 主 SKILL.md 只保留简要调用；本文件是成品层与输出契约的唯一 Source of Truth。
> 适用范围：**所有平台、所有类型（普通/IP）、所有目的（内容/种草/卖货）的最终成品。**
> 核心目标：**最终成品像不像真人、像不像这个平台、像不像这个账号。**
> 解决：AI 感、模板感、模块拼接感、信息堆砌、产品说明书感、IP 人格不足、专业表演感、多版本只换开头、四平台只换长度、CTA 突然变营销腔、为卖货自动补有利事实、每篇过度完整、每篇强行总结升华造金句。
> 最高原则：**策略决定写什么；平台决定怎么说；人设决定谁在说；事实决定能说到哪；真人感决定用户信不信。最终成品必须像真实创作者，而不是像 AI 把规则全部执行了一遍。**

---

## 一、真人内容原则（所有平台共同遵循）

所有平台共同遵循：

- **自然 > 完整**
- **连贯 > 模块齐全**
- **具体 > 抽象**
- **判断 > 套话**
- **真实场景 > 营销话术**
- **一个重点讲透 > 所有卖点讲一遍**
- **平台原生 > 一稿多发**
- **事实弱一点 > 编一个更好卖的结论**
- **长期信任 > 一次刺激**
- **结构必须藏在内容下面。**

用户最终不应该感觉："这篇用了 PAS/AIDA/SCQA。"
而应该感觉："这个人本来就会这么说。"

---

## 二、信息减法层（生成前必做）

生成前先把全部信息分成四类：

| 类别 | 定义 | 处理 |
|---|---|---|
| 必讲 | 不讲就无法完成第一目标 | 必须保留 |
| 辅助 | 能增强理解、信任或体验 | 按平台限额保留 |
| 可删 | 真实，但和当前角度无关 | 删除 |
| 禁止 | 事实不足、推导过度或合规风险 | 删除 |

**平台限额：**

- **短视频**：1 个核心观点/卖点 + 最多 2 个辅助证明。
- **小红书**：围绕一个明确问题展开，所有细节必须帮助用户做判断。
- **公众号**：允许多个论据，但只能服务一个主观点。
- **视频号**：一个真实问题 + 一个主要判断即可，不做知识百科。

**删除判据**：如果一句话只是"这个信息也挺有用"，但不服务当前第一目标 → 删除。

---

## 三、过度完整检测

AI 不能因为知道得多，就全部写出来。每篇内容允许：

- 不讲所有卖点
- 不讲所有参数
- 不做完整总结
- 不升华
- 不强行金句
- 不强行 CTA
- 不把所有异议都解决完

**特别是短视频：一个事情讲明白，比六个信息讲一遍更重要。**
如果同一核心观点已经有 2 个证据：第三个同类证据默认删除。

---

## 四、自然连贯检测（逐句检查）

逐句检查：**为什么这句话之后，会自然出现下一句话？**

必须至少存在一种关系：

- 因果
- 追问
- 动作
- 观察
- 反应
- 转折
- 判断
- 举例
- 场景推进
- 情绪推进

如果下一句出现的唯一原因是"模板下一步该讲这个"，则判定为**模块拼接**，必须重写。

---

## 五、专业表演感检测（IP 内容）

IP 内容尤其容易出现"为了证明自己专业，不停解释知识"。

**规则**：当 IP 已经给出一个明确判断后，最多用 **2 个证据**证明。

**优先证据顺序：**
1. 真实动作
2. 现场观察
3. 选择标准
4. 真实对比
5. 必要知识解释

不要优先长篇科普。如果一段让用户明显感觉"这个人在努力证明自己懂行"，删除至少 30% 的专业解释。

---

## 六、人格动作（IP 内容）

IP 不是多写"我"。每篇 IP 应至少形成一个 **Persona Signal**：

优先（当前状态，不依赖历史）：

- Current Judgment（当前判断）
- Current Preference（当前偏好）
- Selection Standard（选择标准）
- Value Principle（价值原则）
- Tradeoff Logic（取舍逻辑）

只有 IP Fact 支持时才能使用：

- past refusal（过去的拒绝）
- long-term insistence（长期坚持）
- historical change（历史改变）
- personal experience（个人经历）

例如（当前判断优先）：

- 我不太看重……
- 我更在意……
- 这种东西我一般不会推荐……
- 我选这类产品先看……
- 这个问题我和很多人看法不一样……

**Current judgment is enough to build persona.** 禁止虚构经历；平台原生不能反向制造 IP 经历。

---

## 七、普通内容不要强行 IP 化

当模式是普通内容时，不要为了真人感强塞：

- 我的经历
- 我的标准
- 我的朋友
- 我的客户
- 我用了多久

普通内容的真人感来自：**自然表达 + 真实场景 + 清楚判断 + 具体信息。** 不是强行人设化。

---

## 八、事实分层（所有平台统一）

| 层级 | 定义 |
|---|---|
| 品类事实 | 关于品类的一般知识 |
| SKU 事实 | 当前具体产品事实 |
| 品牌事实 | 当前品牌事实 |
| IP 事实 | 创作者本人真实经历和判断 |
| 用户事实 | 真实反馈或数据 |
| 合理推导 | 由事实可以合理推出的使用价值 |
| 未知 | 不能写 |

**禁止：**
- 品类事实 → 自动变 SKU 事实
- SKU 事实 → 自动变 IP 亲身体验
- 工艺 → 自动变功效
- 常见情况 → 自动变当前产品确定结论

---

## 九、有利推导禁令（商业文案）

不得为了让产品更好卖，自动补以下表述：

- 更适合
- 不刺激
- 不苦不涩
- 不容易坏
- 不受潮
- 锁鲜
- 性价比高
- 比别人省钱
- 不挑人
- 谁都适合
- 送礼不会出错
- 一定耐泡
- 一定回甘
- 一定好喝
- 一定适合冷泡
- 长辈适合
- 小孩适合
- 孕妇适合
- 一定复购

如果事实表没有明确支持：删除或降低确定性。

## 十、四平台原生真人感

### 抖音：正在发生

不是"在介绍一个产品"，而是"人在拿、拆、试、看、问、判断"。

优先：
- 动作
- 现场
- 反应
- 用户问题
- 一句判断

抖音稿尽量寻找 **1-3 个真实可拍动作**（拿起 / 拆开 / 倒出来 / 对比 / 泡 / 闻 / 看 / 试）。
连续 80 字以上只有对镜头干讲：优先重构。

### 小红书：帮用户做选择

不是"广告装成分享"，而是"我把真实选择逻辑给你"。

重点：
- 为什么选
- 为什么不选
- 适合谁
- 不适合谁
- 真实优点
- 必要缺点
- 使用场景
- 对比
- 避坑
- 细节

小红书不要靠"姐妹们、绝绝子、闭眼冲"制造平台感。

### 公众号：有人真的想过这件事

不是口语化。允许书面表达。但必须有：
- 主观点
- 判断
- 推进
- 解释
- 案例
- 思考

禁止写成 AI 资料整理。每部分都必须推动主观点。

### 视频号：现实中值得信任的人

更像：老板 / 老师 / 专业人士 / 有阅历的人 / 家庭里的可靠角色。

减少：
- 猛刺激
- 猛反转
- 极端话
- 网络热梗

增加：
- 稳定判断
- 解释
- 经历
- 现实场景
- 熟人传播价值

视频号绝不能只是"放慢语速的抖音"。

## 十二、多版本叙述姿态差异（Creative Variation）

Creative Variation 模式下，不能只换选题和开头。增加叙述姿态变量：

- 直接判断
- 回答用户问题
- 现场演示
- 经验提醒
- 对比选择
- 聊一件事
- 拆误区
- 使用场景
- 用户决策
- 真实观察

如果生成 5 版：至少使用 **3 种不同叙述姿态**。
禁止 5 版全部"判断开头 → 专业解释 → 产品 → CTA"。

---

## 十三、去头测试

删除每一版前 20%。如果后 80% 内容：

- 卖点顺序高度相同
- 证据高度相同
- CTA 高度相同
- 产品说明高度相同

则判定为**伪多版本**，必须重写。

---

## 十四、金句限额

每篇最多 **1 句**：
- 对仗
- 升华
- 高度概括
- "可以摘出来发朋友圈"的句子

如果正文已经有鲜明判断：结尾不再强行升华。

禁止每篇都写成：
- "X 不是 A，而是 B"
- "真正的 X……"
- "X 出去是 A，回来是 B"

真人不会每条内容都留下名言。

---

## 十五、CTA 三层翻译

CTA 不是直接从商业目标生成。必须经过：**目的 → 平台 → 人格**。

例如同样"购买"：

| 平台 | 收口方向（机制示意，非可直接照抄句） |
|---|---|
| 抖音 | 判断 + 现场感，收在"自己判断"上 |
| 小红书 | 帮用户做选择，收在选择标准上 |
| 公众号 | 理性判断，收在"需求是否一致"上 |
| 视频号 | 保护长期信用，收在"适合自己再考虑"上 |

CTA 必须与正文是同一个人。**CTA 权限规则只定义在 `references/craft/cta.md`（Source of Truth：CTA），本文件只引用，不重新定义显式 CTA 许可条件。** 默认 IMPLICIT_ONLY；显式 CTA 仅命中 Closed Allowlist 时允许。

---

## 十六、自然结束检测

完成正文后：删除最后一句。如果内容已经自然成立，检查最后一句是否只是为了：

- 总结
- 金句
- 升华
- 强行互动
- 强行成交

而存在。如果是：删除。
不是所有内容都必须有明显的"结尾"。

---

## 十七、平台互换测试

生成后把平台标签去掉，检查：

- **抖音稿**：直接发小红书是否仍然完全成立？是 → 平台原生性不足。
- **小红书稿**：删掉几个换行能否直接变公众号？是 → 平台原生性不足。
- **视频号稿**：加一个强钩子是否直接变抖音？是 → 平台原生性不足。
- **公众号稿**：缩短后是否只是普通短视频稿？是 → 平台原生性不足。

任一成立：说明平台原生性不足，必须重写。

## 十八、Humanization Pass 3.0（Draft 完成后强制执行）

> v2.5 起：Humanization 阶段**只有表达权限，没有事实权限**（完整规则见 `expression-authority.md` 第十八节）。

**只允许**：
- 删除
- 调整顺序
- 口语化
- 增加停顿
- 调整节奏
- 改表达方式
- 增强平台感

**禁止在这个阶段新增**：
- 产品事实
- 人物经历
- 用户评价
- 数据
- 功效
- 用户结果
- 市场判断
- 新适合人群

**执行步骤：**

1. 删除至少 10%-20% 不必要信息。
2. 删除同义重复。
3. 删除第三个以上的同类证明。
4. 检查每一句为什么接下一句。
5. 把产品说明句改成：动作 / 判断 / 场景 / 观察。
6. 检查是否过度证明专业。
7. 检查金句是否过多。
8. 检查 CTA 是不是同一个人在说。
9. 检查平台互换。
10. 朗读测试。
11. 事实扩张测试：每句问"比原始事实多了什么"，新增信息删除。
12. IP Fact Firewall 复查：无 IP 资料的第一人称经历删除。

## 十九、朗读测试

短视频最终稿必须进行**口头朗读模拟**。出现以下情况必须改：

- 一口气说不完
- 书面词太多
- 连续解释太长
- 逻辑虽然对但说出来别扭

但真人感不等于：
- 故意语病
- 故意错别字
- 大量"啊、呢、嘛"
- 家人们
- 宝子
- 哈哈哈

自然即可。

使用同一个产品或主题分别生成：抖音 / 小红书 / 公众号 / 视频号。

要求：不能只是修改长度 / emoji / 标题 / 语气。
必须改变：

- 入口
- 用户心理
- 信息组织
- 证据
- 表达姿态
- CTA
- 最终传播理由

## 二十二、成品层检查维度（每个 case 额外检查）

- **真人感**：像不像人？
- **平台感**：像不像这个平台？
- **人格感**：IP 模式下是谁在说？
- **连贯性**：是不是一句自然接一句？
- **减法**：有没有多余信息？
- **事实**：有没有为了好卖自动补结论？
- **同质化**：换一个版本是不是基本一样？

---

## 最终成功标准

- **抖音**：像人在镜头前边做边说。
- **小红书**：像真实的人在帮我做选择。
- **公众号**：像一个作者真正想明白以后写出来。
- **视频号**：像现实中一个值得信任的人在讲话。
- **普通内容**：内容本身成立。
- **IP 内容**：能感受到是谁在说。
- **种草**：产生偏好，不急着逼单。
- **卖货**：减少决策阻力，不靠夸张刺激。
- **多版本**：不是换开头，而是真的换思路。
- **多平台**：不是改长度，而是真的换表达逻辑。

## 二十三、Humanization Pass 升级（v2.6 同步）

Humanization 最后不再问"有没有真人感元素？"，而是问：

> **这是不是像这个人在这一次具体场景中自然说出来的？**

Humanization 只做：删除 / 合并 / 调序 / 自然化 / 动作化 / 平台化 / 去规则痕迹。

**禁止：为了满足 IP / 边界 / CTA / 金句 / 平台感，再新增一个专门模块。** 真人感不是加入更多真人元素，而是减少 AI 过度完整、过度规则化的痕迹。

## 二十四、5 个最终验收问题（v2.6 新增，每篇生成完内部回答）

1. **目标**：这一篇有没有完成当前 24 模式的中心心理变化？
2. **平台**：如果去掉平台标签，表达方式还能体现平台原生性吗？
3. **人格**：IP 模式下，这个人是谁，能不能感受到？
4. **自然**：有没有明显看到模板、QA 项或规则执行痕迹？
5. **必要**：正文中的每一块信息真的都需要吗？如果答案是"不需要，但写了更完整"→ 删除。

## 二十五、与 Natural Depth Layer 的衔接（v2.7）

> 完整规则见 `natural-depth.md`（Source of Truth：自然充分度层）。本文件管"成品像不像真人"，Natural Depth 管"讲到什么程度才够"。两者必须串联。

### 25.1 信息减法不能减到模式目标消失

信息减法层决定"减到什么程度"，Natural Depth 决定"减到什么程度**才够**"。两者共同作用：

- **减法负责删掉不必要的**：不服务第一目标的信息、同类证据超过 2 个、为凑字数补的解释/金句/总结。
- **Natural Depth 负责保住必要的**：当前模式的心理目标、IP Asset、SKU 选择理由、关键决策信息。

**禁止把"信息减法"当成"越少越真人"的借口。** 如果减完以后用户只得到"一个结论 + 产品名"，说明减过头了，进入 Natural Depth 修复。

### 25.2 自然连贯检测与 Conversational Flow Check 合并执行

本文件第四节"自然连贯检测"（逐句检查为什么下一句接这一句）与 Natural Depth 的 Conversational Flow Check 合并执行：

- 每 3—5 句检查一次：**下一句为什么会接在上一句后面？**
- 如果只能回答"因为还有另一个卖点没说"→ 失败。
- 连接方式：因果 / 追问 / 动作 / 用户反应 / 判断 / 解释 / 比较 / 现场观察 / 场景推进。
- **短句是结果，不是方法。** 真人表达必须存在连续话流，禁止"产品事实一句/参数一句/工艺一句/体验一句/CTA一句"的短句提词器。

### 25.3 自然结束检测必须通过 Completion Gate

本文件第十六节"自然结束检测"（删除只为总结/金句/升华/强行互动/强行成交而存在的结尾）与 Natural Depth 的 Completion Gate 合并执行：

**可以没有正式结尾，但结束前必须检查：**

- **First Goal**：完成了吗？
- **Mode**：没有漂移吗？（卖货没漂移成内容/种草）
- **IP Asset**：IP 模式下形成了吗？
- **Product Relevance**：商业任务里 SKU 选择理由存在吗？

**没有通过，不能结束。** 留白是"删掉不必要的"，不是"把必要的也删掉"。

### 25.4 字数采用 Soft Range

本文件与 `anti-patternization.md` 的"字数是区间不是 KPI"原则一致，但补充：**Natural Completion ≠ Minimal Length。**

- 用户说"每版 300 字左右"→ 合理软区间约 **220—330 字**，由 Angle Complexity / Mode Completion / Platform / First Goal 决定。
- 如果 240 字已经充分就停止；如果 180 字导致 IP、SKU 理由或卖货决策不足就继续写。
- **禁止把"越短越自然"当成默认策略。**

### 25.5 平台原生真人感与平台角度发现分开

本文件第十节"四平台原生真人感"决定**这个平台怎么表达**；Dynamic Angle Discovery 决定**这个平台值得讲什么**。平台从选题阶段就介入，不能先选 5 个角度再做平台适配。平台角度发现指引见 `dynamic-angle-discovery.md` 第六节与 `platforms.md` 新增"平台角度发现"节。

### 26.2 输出内容（默认）

用户只要文案时，只输出：
