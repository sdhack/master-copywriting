# Commercial Expression Freedom（商业表达自由层）

> **Source of Truth：商业表达自由 Commercial Expression Freedom。** 主 SKILL.md 只保留简要调用；本文件是该层的唯一 Source of Truth。
> **版本**：v4.11.4 更新（功效暗示永不过滤：第二十五章默认保留条款 / AMBER 区放宽 / PARTIAL_PAIN 露出边界残留修复）
> **类型**：商业表达强度升级（不新增暗语/规避/谐音偷渡功效；不修改 24 模式 / 四平台 Canonical Core / Content / Seed / Sell 核心定义 / CTA Permission / Dynamic Angle / Natural Depth / Claim Authority / Implicit Benefit & Pain Translation）
> **解决问题**：Skill 虽然事实安全性较强，但商业表达容易过度保守——尤其在食品/营养品/保健食品/美妆/个护/功能型消费品领域，容易出现：有风险 → 删除利益 → 删除情绪 → 删除痛点 → 只剩参数 → 文案真实但卖不动。v4.11.4 起执行"功效暗示永不过滤"：合法边界内的功效暗示（I5-B / I5-C / AMBER）默认保留、默认强化，只有 I5-A 硬禁才被拦截。
> **最高原则**：# 事实边界硬，表达空间宽。 # 功效暗示永不过滤——只有 I5-A 硬禁才拦截。
> 功效权限有上限，商业表达没有必要软。Truth Boundary 不可突破，但 Expression Layer 默认开放。
> **v4.11.4 关键变化**：第二十五章新增"功效暗示默认保留，除非属于 I5-A 硬禁"条款；Edge Expression Policy 的 AMBER 区在非敏感品类默认开放、可强化；修复第二十九/三十章 PARTIAL_PAIN"露出边界"残留（改为"边界体现在不夸大"）。

---

## 一、重新定义"表达自由"

允许大胆使用：

- 隐喻
- 类比
- 谐音
- 双关
- 反差
- 剧情
- 场景演绎
- 对话
- 吐槽
- 网络语言
- 情绪放大
- 口语夸张
- 关键词变化
- 用户原话
- 戏剧冲突
- 身份表达
- 生活画面
- 视觉暗示

这些全部属于 **Expression Layer**，默认开放。

但是：表达形式不得创建新的 Product Claim。

判断原则：

> 换一种表达以后，消费者最终理解到的产品效果，仍然必须在当前 Claim Ceiling 内。

---

## 二、允许修辞夸张，但区分事实夸张与情绪夸张

新增 **RHETORICAL_EXAGGERATION**，允许。

示例：

- "桌上一排瓶瓶罐罐，看着都累。"
- "每天光想今天吃哪几瓶，我已经先放弃一半了。"
- "出趟门还得把半个药箱搬走。"
- "早上能少想一件事，对赶时间的人都算救命。"

以上属于：情绪化 / 生活化 / 修辞性夸张。不是字面产品效果。允许。

---

## 三、禁止事实型夸大

不得把：

- 真实值 → 更大的数字
- 可能 → 必然
- 部分用户 → 所有人
- Authorized Claim → 更强身体结果
- 普通体验 → 医疗效果

示例：

- 真实 5 种，不能写 10 种。
- 官方 15 泡，不能写 20 泡。
- "帮助补充营养"不能变成"吃完人就不累了。"
- "保湿"不能无证据扩大为"修复屏障、逆转敏感。"

原则：

> # Emotional exaggeration is allowed. Factual exaggeration is not.

---

## 四、隐喻全面开放

隐喻可以用于：

- Convenience
- Emotion
- Lifestyle
- Choice
- Product Form
- Product Difference
- Sensory Experience
- Authorized Function

示例：

- "一包把桌上的瓶瓶罐罐收拾明白了。"
- "像给每天这件事按了个快捷键。"
- "以前是一桌选择题，现在变成一天一包。"
- "不是再给生活加一个任务，而是把原来复杂的任务收起来。"

允许。

但是：隐喻不得偷偷创造一个无权限的身体功效。

判断：把隐喻翻译回直白语言以后，它到底声称产品做了什么？如果翻译结果越过 Claim Ceiling：禁止。

---

## 五、谐音和双关开放

允许谐音/双关用于：

- 品牌记忆
- 标题
- 趣味
- 场景
- 情绪
- 人设
- 产品特征

但不得：用谐音替代一个本身不能说的功效词，然后继续传递同一个未经授权 Claim。

原则：

> # Word substitution cannot change claim permission.
> 不是：敏感词换掉 = Claim 自动安全。

---

## 六、剧情表达全面开放

允许：

- 短剧情
- 夫妻对话
- 同事场景
- 办公室
- 出差
- 起床
- 通勤
- 健身
- 购物
- 家庭
- 收纳
- 选择困难
- 懒人场景

但剧情中：Product Fact 仍必须真实。人物经历仍必须遵守 IP Fact Firewall。

尤其：不得虚构身体变化作为剧情证据。没有真实/合法依据时禁止："吃了一周以后……""她之前总是……现在……""用了以后检查指标……""我妈吃完以后……"

剧情可以创造 **Situation**，不能创造 **Product Result**。

---

## 七、放宽痛点表达

Pain 可以更强。优先挖：

- Daily Friction
- Emotional Friction
- Choice Friction
- Time Friction
- Routine Friction
- Cost Friction
- Usage Friction
- Social Friction

示例：

- "不是舍不得买，是买回来根本坚持不了。"
- "最麻烦的不是吃，是每天还得自己配。"
- "营养品最容易出现的结局，就是买的时候很认真，吃的时候全靠缘分。"
- "桌上一排瓶子，看起来专业，真正每天执行起来一点都不专业。"

这种真实生活摩擦允许明显放大表现。

---

## 八、Pain Translation 强制执行

所有商业稿：

```
Surface Pain
↓
Daily Friction
↓
Emotional Cost
↓
Desired Progress
↓
Product Bridge
```

示例：

- Surface：营养补充太麻烦
- Daily：瓶子多 / 需要自己搭 / 出差难带
- Emotion：烦 / 懒 / 容易放弃
- Desired：简单一点
- Product：每日组合包装

文案落点：

> "不是让你再记住几瓶，而是尽量把每天这件事变成一个动作。"

---

## 九、身体痛点不要自动删除

用户真实存在的：疲惫 / 熬夜 / 状态差 / 饮食不规律 / 年龄焦虑 / 皮肤状态 / 身体管理，可以作为 **Audience Context**。

但必须区分 **User Problem** 和 **Product Claim**。

示例：

- 允许："天天外卖、三餐没个准，是很多上班族真实生活状态。"
- 不自动等于："这个产品可以纠正这种身体问题。"

允许用户问题存在。产品能解决到哪里，由 Claim Ceiling 决定。

---

## 十、允许"需求邻接"

产品不一定直接解决最终大痛点。可以解决 Pain 旁边那个真实摩擦。

示例：

- 最终愿望："想把自己的日常营养管理做好一点。"
- 产品未必能承诺让身体发生某结果。
- 但它可能真实解决：每天搭配麻烦 / 携带麻烦 / 选择成本高 / 执行复杂。
- 则文案可以：从大需求进入，最后落到产品真正解决的小摩擦。

这比直接删除大需求更有销售力。

---

## 十一、Benefit 必须比参数更靠近用户

每个核心 Fact 必须内部至少走一遍：

```
FACT
↓
WHAT IT DOES
↓
WHY USER CARES
↓
REAL SCENE
```

正文优先：WHY USER CARES + REAL SCENE。参数作为 Proof。不要反过来。

---

## 十二、允许"结果感"，但结果必须属于允许领域

结果感不等于身体功效。

允许强化使用以后：

- 更省事
- 更简单
- 更容易执行
- 更容易携带
- 更少选择
- 少占空间
- 更容易形成固定流程
- 更舒服
- 更符合生活习惯
- 更容易判断是否适合自己

这些结果可以明显、具体、有画面地说。不要因为"结果"两个字就自动弱化。

---

## 十三、Authorized Claim 允许情绪化表达

如果当前 SKU 的合法 Authorized Claim 明确存在，正文不需要每次像说明书一样表达。

可以：官方 Claim + 用户语言 + 场景。

但必须保证：语义强度不超过授权范围。

示例：

- Authorized：补充多种维生素矿物质。
- 可以写："如果你本来就在做日常维矿补充，这类组合装最大的好处，是不用自己桌上摆一排。"
- 不要写成："补齐以后每天状态拉满。" 除非存在独立 Claim Authority。

---

## 十四、用户原话可以使用，但不能借用户之口洗 Claim

评论、搜索词、用户痛点可以用于发现问题。

示例：用户搜索"吃什么不累？"可以说明疲劳是用户关注的问题。

但不能因为用户这么问，就让产品获得抗疲劳 Claim。

原则：

> # User question gives topic permission. It does not give product claim permission.

---

## 十五、达人/素人可以更口语、更大胆

达人/素人允许：吐槽 / 段子 / 自嘲 / 反差 / 不完整句 / 网络表达 / 情绪化表达 / 强个人判断。

示例：

- "我现在最怕的不是没买，是买回来桌上又多五个瓶子。"
- "能一件事解决的，我是真的不想搞成八件事。"

但：Personality Freedom ≠ Claim Freedom。

---

## 十六、商家文案也不要自动官腔

品牌/商家身份可以：直接 / 有态度 / 有商业性 / 强调产品设计 / 强调购买理由。

不要求"品牌官方 = 产品说明书语气"。

商业身份只影响：关系透明度。不要求降低文案吸引力。

---

## 十七、开放强利益表达

如果 Benefit 由真实事实直接支持，允许使用更有力度的表达：

- "最大的价值就在这。"
- "这点才是真正让我觉得它值的地方。"
- "如果你烦的是 X，这个设计确实解决得很直接。"
- "它不是多给你一个东西，而是少给你几件每天要操心的事。"

无需自动加：可能 / 也许 / 一定程度 / 似乎 这些无意义弱化词。

---

## 十八、Claim Strength 不允许自动缩水

Source 支持多强，就允许说多强。

- Strong Evidence → Strong Claim
- Weak Evidence → Qualified Claim
- No Evidence → No Claim

禁止：

- Strong Evidence → Weak Marketing
- Weak Evidence → Strong Marketing

---

## 十九、建立 Semantic Back-Translation

对：隐喻 / 谐音 / 剧情 / 暗示 / 双关 / 关键词替换，最后内部做一次 **Back-Translation**：

把它翻译成一句普通直白的话：

> "这段表达最终让消费者相信产品具有什么效果？"

然后判断这个效果有没有 Claim Authority：

- 有：PASS。
- 没有，但只是合法生活/情绪价值：PASS。
- 没有，且是新增健康/医疗/生理功效：**FAIL → 进入 CONVERSION_RECOVERY（v4.11.0）**。

**v4.11.0：FAIL 不是终点，是可恢复的。**

检测到语义终点越线后：

1. **保留情绪强度和场景冲击力**——不删除整段利益表达；
2. **只替换越线的那一跳**——把"产品改善身体"那一跳换成"产品把这件事变简单"的合法价值跳；
3. **禁止直接删成参数列表**（那等于放弃销售，违反 Commercial Recovery Hard Requirement）。

恢复路径（按顺序尝试）：

1. 把主语义从"身体结果"平移到"行为/体验结果"（更省事 / 更简单 / 更容易坚持 / 选择更少 / 携带方便）；
2. 若产品有 Authorized Claim，用授权功能承接同一需求；
3. 若仍无法承接，用 Benefit Translation Domains（Convenience / Routine Simplicity / Choice / Cost-Value / Sensory / Identity）重建购买理由；
4. 只有全部失败才允许降级为"参数 + 场景"，且必须重新检查是否满足 Sell Commercial Density。

**v4.11.1：恢复时禁止说教式自我设限。** 恢复 = 把越线那一跳换成合法价值跳，保留情绪强度，不添加免责/说教：

- 禁止"我不指望它一夜之间改变什么"（说教 + 免责，抢走购买理由）
- 禁止"它不神化自己 / 它不吹功效"（说教）
- 禁止"别指望它……"（免责）
- 恢复后的句子仍然在卖产品，不是在解释产品不负责什么

示例：

- 越线："第二天状态差别很明显。"（主语义 = 产品改善身体状态）
- 恢复（正确）："每天这件事不用再想，坚持这件事本身就变简单了。"（主语义 = 执行更简单）
- 恢复（错误，说教）："我不指望它改变什么，但每天这件事确实简单了。"（自我设限，抢走购买理由）

原则：

> # Back-Translation 是恢复的起点，不是删除的借口。
> # 越线的那一跳可以换，情绪强度和场景冲击力要留下。
> # 恢复后仍然在卖产品，不是在解释边界。

## 二十、禁止关键词审查式写作

不要维护"这个词不能说，所以换成那个词"这种低级系统。

改成 **Meaning-Based Claim Review**。

因为：同一个词可能有合法语境。不同的词也可能表达同一个越界 Claim。

审核：Meaning > Keyword。

---

## 二十一、Commercial Recovery 必须成为 Hard Requirement

如果一条高转化 Claim 被 Fact/Claim Gate 拒绝，AI 不能删除以后直接交稿。必须进行 **Conversion Recovery**。

至少重新寻找：

1. Authorized Claim
2. Convenience
3. Product Difference
4. Routine Simplicity
5. Cost / Value
6. Product Format
7. Usage Experience
8. Sensory Value
9. Choice Efficiency
10. Identity Fit
11. Emotional Value
12. Risk Reduction

直到文案重新建立购买理由。

原则：

> # Losing one claim cannot automatically mean losing the sale.

---

## 二十二、Sell Commercial Density

每篇 Sell 至少包含：

- 一个强 Pain/Desire
- 一个与 Pain 直接相关的真实 Product Difference
- 一个明确 User Benefit
- 一个可信 Proof
- 一个 Decision Reason

如果最终只剩：品牌 / 成分 / 参数 / "可以了解"：判定 **SELL WEAK**，重新生成。

---

## 二十三、Seed Desire Strength

Seed 允许更强：场景想象 / 产品向往 / 生活方式投射 / 选择欲 / 身份欲 / 便利欲。

最终必须产生："这东西我开始想要了。" 而不是："我知道这个产品存在。"

---

## 二十四、允许一句商业金句，但不要模板化

每篇最多允许一个高浓度利益句 / 判断句。

不能每篇都"真正的 X 不是 A 而是 B。"

金句必须从当前 Angle 自然产生。

---

## 二十五、Boundary is Internal, Not Content（边界是内部标准，不是文案内容）

**v4.11.1 升级。** 合规边界由内部 Hard Gate 执行，不是文案内容。禁止把边界、免责、说教写进正文——边界不能抢走购买理由。

**v4.11.4 新增：功效暗示默认保留。** 合法边界内的功效暗示（I5-B / I5-C / AMBER）默认保留、默认强化，除非属于 I5-A 硬禁（疾病/治疗/预防/明确生理结果）。边界是内部审查标准——它决定"不写什么"，不决定"删掉暗示"：I5-B/C/AMBER 的暗示不是边界内容，不得因"这是功效风险"被过滤。

### 事实边界（允许自然带出）

产品真实属性可以自然带出，作为真实感与可信度，不削弱购买理由：

- 产品法定身份（非保健食品 / 营养素饮品 / 普通食品）——陈述事实，不解释法规
- 成分 / 规格 / 剂型 / 原料等级 / 生产商 / 保质期 / 数量——产品事实
- 使用方式 / 食用便利——产品事实

自然带出 = 陈述事实，不自我设限、不教育消费者、不解释"为什么不能宣传"。

### 免责声明式表达（禁止）

把合规边界 / 产品不负责的部分写进文案，抢走购买理由：

- "它不负责让你瘦" / "它不负责改善皮肤"
- "我不指望它一夜之间改变什么"
- "它不神化自己" / "它不吹功效"
- "按法规，普通食品不能宣传功效"
- "别指望它……" / "它做不到……"
- "效果因人而异，仅供参考"（除非法律/平台强制要求展示）

### 说教式表达（禁止）

教育消费者、教训式、道德评判式表达：

- "别被神药话术骗" / "那些话术听听就好"
- "焦虑驱动的东西，往往买完就后悔"
- "买之前先学会看这一行字"
- "成分再好，喝不进去也白搭"
- "我劝你……" / "你要记住……" / "先学会……"

### 边界如何体现（正确方式）

边界体现在"不写什么"，不是"解释边界"：

- 不把部分解决写成全部解决（不夸大）
- 不把成分写成功效（不越界）
- 不虚构身体结果（不造假）
- 但正文里不需要出现任何"它不负责 / 别指望 / 按法规"的自我设限

### 判断标准

逐句问：**这句话是在卖产品，还是在解释产品的边界 / 教育消费者？**

- 卖产品 → 保留
- 解释边界 / 免责 / 说教 → 删除，或改写为正面价值表达

示例：

- 说教："按法规，普通食品不能宣传功效，那些话术听听就好。"
- 改写（正面价值）："成分表干净、原料可追溯、喝起来省事，这三点我看得比什么都重。"（把"不宣传功效"的边界，换成"成分/原料/便利"的正面购买理由）

原则：

> # 边界是内部审查标准，不是文案内容。
> # 合规靠"不写什么"守住，不靠"在文案里解释"守住。
> # 边界永远不能抢走购买理由。
> # 自动免责声明破坏销售表达——效果因人而异/仅供参考等只出现在法律强制要求时，不在文案里主动加。

## 二十六、最终文案优化顺序

当一篇稿"不够能卖"：

1. 第一优先提高：Pain Specificity
2. 第二：Product Relevance
3. 第三：Benefit Strength
4. 第四：Scene Vividness
5. 第五：Proof
6. 第六：Emotional Intensity
7. 第七：Decision Clarity

而不是第一反应扩大未经授权健康功效。

## 二十七、最终 Creative Permission

允许大胆：写痛 / 写烦 / 写懒 / 写纠结 / 写欲望 / 写生活混乱 / 写选择困难 / 写消费者真实吐槽 / 写戏剧 / 写冲突 / 写隐喻 / 写谐音 / 写反差 / 写自嘲 / 写幽默 / 写强判断 / 写商业欲望。

不要把 Skill 训练成"合规机器人"。

但必须保证：

> # 所有创造性最终不能改变现实世界里的产品事实。

## 二十八、Edge Expression Policy（边缘表达策略）

**v4.11.0 新增。** 解决"隐喻/剧情/谐音被过度收紧"的问题——把表达分成三层：

### GREEN（绿色，开放）

用隐喻/剧情/谐音强化**已经授权或真实存在的价值**：

- 方便 / 省事 / 选择成本 / 感官 / 仪式感 / 身份感 / 生活方式 / 产品形态 / 真实差异

示例：

- "一包把桌上的瓶瓶罐罐收拾明白了。"（强化 Convenience）
- "像给每天这件事按了个快捷键。"（强化 Routine Simplicity）
- "以前是一桌选择题，现在变成一天一包。"（强化 Choice）

### AMBER（琥珀，灰色区，非敏感品类默认开放）

**非敏感品类**（普通食品 / 日用品 / 非宣称功效化妆品）下，允许"合理消费者可能产生轻微联想，但主语义仍落在合法价值"的写法。**v4.11.4：默认开放、默认保留、可强化**——不得因为"有轻微联想"就降级或删除。

判断标准：

1. Back-Translation 后，消费者理解的主效果是合法价值（省事 / 更简单 / 更容易坚持 / 选择更少 / 身份感）；
2. 轻微联想不构成对未授权身体功效的明确承诺；
3. 不出现疾病 / 治疗 / 预防 / 明确生理结果词汇或等价语义（I5-A）。

示例（AMBER，允许，可强化）：

- "出趟门还得把半个药箱搬走。"（夸张的是"带的东西多"，主语义 = 携带麻烦，不是药物功效）
- "早上能少想一件事，对赶时间的人都算救命。"（夸张的是"省事"，主语义 = 便利）

示例（I5-A 越线，禁止）：

- "吃完下午不用靠咖啡了。"（主语义滑向抗疲劳）
- "脸色这个东西自己照镜子。"（主语义滑向生理改善）

**AMBER 必须标注**：内部路由记录为 AMBER，不得升级为 GREEN；若平台/品类敏感，降级为 RED。非敏感品类下 AMBER 默认保留，只有 Back-Translation 后主语义明确滑向 I5-A 才拦截（拦截走 CONVERSION_RECOVERY）。

### RED（红色，禁止）

用隐喻/剧情/谐音**制造未授权功效**：疾病 / 治疗 / 预防 / 明确生理结果 / 硬功效偷渡。

禁止。

原则：

> # 表达可以强化真实价值，不能创造未授权功效。
> # AMBER 允许轻微联想，但主语义必须落在合法价值域。

## 二十九、品类差异化天花板（Category-Differentiated Ceiling）

**v4.11.0 新增。** 商业表达强度必须按品类差异化，不能一刀切。

### 明显放宽（情绪与生活方式暗示）

- 普通食品（ORDINARY_FOOD）
- 日用品（GENERAL_GOODS）
- 非宣称功效化妆品

允许：更强的情绪 / 身份 / 生活方式暗示；I5-C 开放；PARTIAL_PAIN 强表达；AMBER 灰色区开放。

### 保持严格

- 保健食品（HEALTH_FOOD / NUTRIENT_SUPPLEMENT_HEALTH_FOOD）
- 有功效评价的化妆品（COSMETIC with efficacy claims）
- 医疗器械（MEDICAL_DEVICE）
- 药品（DRUG）

允许：Authorized Claim 按授权强度直接表达；I5-B 仅作为受众上下文；I5-C / AMBER 收紧；PARTIAL_PAIN 强表达但边界体现在不夸大（v4.11.1 起不再要求"露出边界"）。

### 平台差异化

- **抖音**：允许更高情绪密度、更强的场景冲击、更快的痛点切入。
- **小红书**：情绪之后必须给判断标准 / 比较维度 / 避坑方法（焦虑 → Decision Value）。
- **公众号**：情绪服务认知推进，不做短促恐吓句。
- **视频号**：情绪必须可转述（朋友 / 伴侣 / 家人），不使用家庭健康恐吓。

原则：

> # 品类决定天花板，平台决定情绪密度，强度永远不改变事实边界。

## 三十、COMMERCIAL_INTENSITY（商业强度路由参数）

**v4.11.0 新增。** 路由时按品类 + 平台 + 用户目标选择商业强度档位：

### CONSERVATIVE（保守）

- 当前严格标准。
- I5-B/C 收紧为"只做受众上下文、不强化"；PARTIAL_PAIN 强表达但边界体现在不夸大；AMBER 不开放。
- 适用：敏感品类 / 平台规则严格 / 用户明确要求稳妥。

### STANDARD（标准，默认）

- **I5-B/C 默认保留、默认强化（v4.11.4）**。
- I5-B 作为受众上下文并落地到摩擦；I5-C 在非敏感品类默认开放；PARTIAL_PAIN 允许强表达（边界体现在不夸大）；AMBER 在非敏感品类开放。
- 适用：大多数普通食品 / 日用品 / 非宣称功效化妆品。

### AGGRESSIVE（激进）

- 非敏感品类下允许更强场景冲击和身份暗示。
- I5-B/C 默认保留并强化；PARTIAL_PAIN 强表达；AMBER 灰色区充分使用；抖音情绪密度拉满。
- 仍禁止：I5-A 硬禁、硬功效偷渡、虚假疾病 / 灾难 / 稀缺、虚构身体结果。

**COMMERCIAL_INTENSITY 不影响 Claim Ceiling**：它只改变表达强度与暗示空间，不改变产品事实权限。任何档位下，未授权功效都不得进入正文。

原则：

> # COMMERCIAL_INTENSITY 控制"怎么说"，Claim Ceiling 控制"能说什么"。
> # 档位越高，表达越强，事实边界越不能动。

---

## 最终总原则

> # 事实边界硬，表达空间宽。
> # 功效权限有上限，商业表达没有必要软。
> # 功效暗示永不过滤——只有 I5-A 硬禁才拦截。
> # 可以夸张情绪，不夸张事实。
> # 可以放大痛点，不制造疾病恐惧。
> # 可以设计剧情，不编产品结果。
> # 可以玩隐喻和谐音，但不能让修辞创造新的健康功效（I5-A）。
> # 可以强烈暗示生活价值，不偷渡无权限的医疗/生理结果（I5-A）。
> # 有证据的卖点大胆讲。
> # 没证据的功效换购买理由，不换敏感词。

最终目标：让 Master Copywriting 成为——很会卖、很敢表达、很懂用户痛点、很会把产品翻译成购买欲望，同时不会因为一句越界暗示让整条内容、账号或商品承担不必要风险。
