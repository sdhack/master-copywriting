# Anxiety Activation & Pain Scenification（焦虑激活 × 痛点场景化引擎）

> **Source of Truth：焦虑激活与痛点场景化 Anxiety Activation & Pain Scenification。** 主 SKILL.md 只保留简要调用；本文件是该层的唯一 Source of Truth。
> **版本**：v4.11.0 更新（品类差异化焦虑强度 / PARTIAL_PAIN 同步 / COMMERCIAL_INTENSITY 联动）
> **类型**：商业表达强度升级（不新增暗语/规避/谐音偷渡功效；不修改 24 模式 / 四平台 Canonical Core / Content / Seed / Sell 核心定义 / CTA Permission / Dynamic Angle / Natural Depth / Claim Authority / Implicit Benefit & Pain Translation / Commercial Expression Freedom）
> **解决问题**：Skill 虽然会识别痛点，但经常出现——痛点太抽象、场景不具体、用户没有"这就是我"的感觉、后果感太弱、没有继续拖下去的成本、产品出现前缺乏购买动机、文案正确但没有紧迫感。
> **最高原则**：# Make the real problem feel real. 不是：# Invent a bigger problem.
> 不得通过虚假疾病、虚假灾难、虚假稀缺等创造不存在的危险。
> **v4.11.0 关键变化**：焦虑强度按品类差异化（非敏感品类允许更高情绪密度，敏感品类收紧）；痛点距离同步为 DIRECT_PAIN / PARTIAL_PAIN / CONTEXT_PAIN；焦虑强度与 COMMERCIAL_INTENSITY 联动。

---

## 一、建立完整 Pain Chain

任何商业内容不要停留在"用户有 X 痛点"。必须继续向下拆：

```
P1 — Surface Problem    用户嘴上说的问题
P2 — Trigger Scene      这个问题具体什么时候发生
P3 — Friction           当时到底哪里麻烦
P4 — Emotional Cost     它让用户产生什么情绪
P5 — Repeated Cost      如果反复发生，用户持续损失什么
P6 — Anxiety            用户真正担心的是什么
P7 — Desired Escape     用户最希望结束哪种状态
P8 — Product Bridge     当前 SKU 凭什么接住这个问题
```

完整链路：

```
Problem → Scene → Friction → Cost → Anxiety → Desired Change → Product
```

---

## 二、禁止抽象痛点直接进入正文

抽象痛点必须先具体化。例如：

❌ "现代女性生活节奏快，营养补充很重要。"（太抽象）

必须继续问："节奏快到底表现在哪里？"可以落到：

- 早上来不及
- 经常外卖
- 出差
- 桌上一堆瓶子
- 今天吃哪个都要想
- 买了但总忘
- 一周坚持三天
- 临出门又懒得装

正文优先写**可看见的麻烦**，不是概念。

---

## 三、Pain Scene 必须满足 Camera Test

一个痛点场景必须尽量做到：**摄像机能拍出来。**

抽象："补充营养很麻烦。"

场景化："早上已经迟到了，桌上还摆着五六个瓶子，这个两粒、那个一粒，最后一看时间，全推回柜子里。"

用户应该能看到：动作、东西、犹豫、麻烦。

---

## 四、增加 Scene Components

场景可以由以下元素组成：

- **TIME**：什么时候？
- **PLACE**：在哪里？
- **OBJECT**：现场有什么东西？
- **ACTION**：用户正在做什么？
- **INTERRUPTION**：哪里卡住？
- **INNER VOICE**：脑子里在想什么？
- **CONSEQUENCE**：最后发生了什么？

不要求每篇全部出现。至少选 2–4 个形成真实画面。

---

## 五、焦虑不是开场硬吓

禁止直接："你再不解决就晚了。"

优先通过 **Accumulated Friction** 制造焦虑：

- 第一天：麻烦一次。
- 一周：忘几次。
- 一个月：买的东西基本没形成固定使用习惯。

用户自然产生："我是不是又白买了？"这种焦虑比"你必须马上改变"更自然。

---

## 六、建立 Anxiety Types

动态选择最适合当前产品的焦虑类型。

- **A1 Loss Anxiety**：已经花的钱可能浪费。"最怕不是贵，是买回来最后全变成柜子里的库存。"
- **A2 Execution Anxiety**：知道应该做，但长期做不下来。"真正卡人的往往不是第一天，是第十天你还愿不愿意继续。"
- **A3 Decision Anxiety**：不知道怎么选。"越查越多，最后反而不知道到底该买哪一个。"
- **A4 Complexity Anxiety**：步骤太复杂。"每天一件小事被拆成七八个动作，坚持这件事自然就越来越难。"
- **A5 Time Anxiety**：持续拖延。"你一直说下个月再弄，结果同一个问题半年后还在。"
- **A6 Opportunity Cost**：继续旧方案持续浪费资源（钱/时间/空间/精力/注意力/选择成本）。
- **A7 Regret Anxiety**：害怕最后发现"早知道一开始就选简单一点的。"
- **A8 Wrong-Choice Anxiety**：怕买错、规格错、场景不适合。非常适合小红书/对比/卖货。
- **A9 Social Scene Anxiety**：真实社交场景中的选择压力（送礼选错/公开场合不合适/办公室使用麻烦）。但禁止虚构羞辱和社会排斥。

---

## 七、Anxiety Selection 必须与产品相关

禁止为了强刺激随便选择最大焦虑。必须问：**当前 SKU 真正能够降低哪一种焦虑？**

- 产品优势是独立分装 → 最适合 Execution Anxiety / Complexity Anxiety / Portability Friction，而不是疾病焦虑。
- 产品优势是售后政策 → 最适合 Wrong-Choice Anxiety / Purchase Risk。
- 产品优势是价格/大规格 → 最适合 Cost Anxiety / Value Anxiety。

原则：

> # Product Truth chooses the anxiety. 不是：Anxiety forces the product to fit.

---

## 八、增加 Cost Layer

痛点不能只是"很烦"。进一步量化或具体化用户到底付出了什么：

- **TIME COST**：时间
- **MONEY COST**：钱
- **MENTAL LOAD**：脑力
- **ATTENTION COST**：注意力
- **SPACE COST**：空间
- **EFFORT COST**：操作
- **DECISION COST**：选择
- **EMOTIONAL COST**：烦躁、后悔、内耗
- **SOCIAL COST**：真实社交场景的不便
- **ROUTINE COST**：破坏习惯

如果没有真实数字：不要编数字。用具体行为表达成本。

---

## 九、建立"继续不解决会怎样"

每个 Sell Angle 内部可以问：**If nothing changes, what realistically continues?**

注意：是继续发生什么，不是制造灾难。例如：

- 继续忘
- 继续闲置
- 继续每天做重复选择
- 继续占地方
- 继续花冤枉钱
- 继续拖延
- 继续在几个方案之间纠结

这种 **Continuing Cost** 允许明显强化。

---

## 十、允许负面未来场景

只要建立在真实逻辑上，允许写："照这个买法下去，半年后柜子里大概率又多一排开封没吃完的瓶子。"

注意：如果"大概率"没有数据支持，最好改成"最容易出现的结果就是……"或直接"最后柜子里又多一排没吃完的瓶子。"

但如果使用第一人称经历：需要 IP Fact。

---

## 十一、Pain Escalation

痛点允许逐层升级：

```
"小麻烦" → "每天重复" → "越来越烦" → "开始影响执行" → "钱/时间已经付出" → "用户开始想换方案"
```

这就是 **Natural Anxiety Build**。不要第一句话就跳到最严重后果。

---

## 十二、建立 Micro-Pain

不要只找"大痛点"。高转化内容往往来自 **Micro-Pain**：

- 每天要开很多瓶盖
- 出差分装
- 忘记今天吃没吃
- 包里瓶子响
- 柜子越来越满
- 每瓶快吃完的日期不同
- 重复下单
- 每次都重新查成分
- 站在货架前不知道选哪个

Micro-Pain：具体、可信、容易代入、广告感低。优先使用。

---

## 十三、痛点之后不要马上上产品

禁止固定"痛点 → 产品出现"。中间可以增加 **Recognition** 或 **Tension**：

```
痛点 → 用户通常怎么解决 → 为什么旧方法仍麻烦 → 用户真正缺的是什么 → 产品出现
```

这样产品不是硬插广告，而是 **Solution Arrival**。

---

## 十四、建立 Failed Solution

允许讨论用户过去常见的解决方法为什么没有解决摩擦：

```
Problem：东西太多。
Old Solution：自己分装。
New Friction：还是要每天整理。
Then：如果当前产品真实支持"预先按天组合"，产品出现。
```

注意：不能虚构竞品缺陷。重点写**旧解决方式本身的摩擦**，不是攻击别人。

---

## 十五、Pain → Product 必须存在 Mechanism

禁止"用户焦虑 → 突然推荐 SKU"。中间必须回答：**为什么当前产品能降低这个摩擦？**

```
Pain：每天自己搭麻烦。
Product Fact：按天组合包装。
Mechanism：减少每天重复搭配动作。
Benefit：执行更简单。
Scene：早上拿一包。
```

链条完整。

---

## 十六、产品不是救世主

产品只解决它真正能解决的那一段问题。例如用户生活很忙，产品不能"解决忙"，但可以"把日常某一个动作变简单"。这种写法反而更可信。

原则：

> # Solve the nearest real friction.

---

## 十七、Pain Specificity Score

内部 0/1/2 评分：

- **0** = 抽象概念。例如"现代人很忙。"
- **1** = 有具体痛点但画面弱。
- **2** = 用户能立刻认出具体场景和摩擦。

**Sell 默认：Pain Specificity 不能为 0。**

---

## 十八、Scene Vividness Score

- **0** = 没有画面。
- **1** = 有场景词。
- **2** = 有动作/物件/时间/冲突中的至少两个。

平台要求：

- **Douyin** 优先达到 2。
- **Xiaohongshu**：至少有可复查、可参考的现实场景。
- **Channels**：场景必须可信、可转述。
- **OA**：可以减少镜头细节，但需要真实问题结构。

---

## 十九、Anxiety Legitimacy Gate

每个焦虑必须通过三个测试：

- **Source Test**：它来自真实用户问题 / 合理生活摩擦 / 搜索评论信号 / 产品本身使用场景 / 用户提供的需求——还是 AI 为了转化自己编的？
- **Reality Test**：即使没有广告存在，这个问题本来会不会发生？
- **Product Relevance Test**：当前产品真的能降低它吗？

三个通过：允许。任何一个失败：换焦虑。

---

## 二十、禁止的焦虑

不得创造：

- 虚假疾病风险
- 虚假身体恶化
- 无证据健康倒计时
- 无依据年龄恐吓
- 虚假育儿危险
- 虚假老人健康风险
- 虚假失去伴侣/家庭后果
- 虚假社会排斥
- 虚假库存
- 虚假涨价
- 虚假最后机会
- 无依据"现在不做以后一定后悔"

---

## 二十一、允许更强的情绪语言

如果底层事实真实，允许：烦死了 / 最怕 / 最容易踩坑 / 最不值 / 最折腾 / 真没必要 / 白花钱 / 越买越乱 / 看着都累 / 最后全闲置 / 根本坚持不下来。

但：强度必须对应用户真实情绪。不要每篇都喊。

---

## 二十二、场景必须服务 Angle

不要为了真人感随机加早晨/办公室/下班/沙发/厨房。场景必须让当前 Angle 更成立：

- Angle = 便携 → 优先出差/通勤/旅行
- Angle = 减少选择 → 优先早晨/每天固定 Routine
- Angle = 性价比 → 优先重复购买/闲置/使用次数

原则：

> # Scene proves the angle.

---

## 二十三、素人 IP 重点加强生活摩擦

素人 IP 不要自动讲专业理论。优先从"我会遇到什么麻烦 / 我为什么懒得做 / 什么让我觉得麻烦 / 我会怎么选"建立真人感。

但不得自动虚构"我以前每天……""我吃了三个月……"。没有 IP Fact 时：使用当前判断 + 泛场景。

---

## 二十四、达人 IP 重点加强选择焦虑

达人更适合：我为什么没选 A / 我更看重什么 / 买这一类我最怕什么 / 我先排除什么 / 什么信息值得看。

用 **Decision Anxiety + Selection Standard** 建立专业信用。仍然不虚构经历。

---

## 二十五、商家重点加强购买风险

品牌/商家可以直接帮助用户解决：买错 / 规格选错 / 不适合 / 不知道怎么用 / 售后担心 / 价格疑虑。

商家不要假装消费者。利用透明、清楚、直接降低焦虑。

---

## 二十六、Seed 和 Sell 的焦虑强度不同

- **CONTENT**：焦虑只是让用户意识问题，不要求产品介入。
- **SEED**：焦虑 → 用户开始想换一种方案。重点：Solution Preference。
- **SELL**：焦虑 → 当前 SKU 解释 → 证据 → 风险降低 → Decision Completion。

Sell 焦虑可以更明确，但不能为了转化制造不存在的严重后果。

---

## 二十六·五、品类差异化焦虑强度（Category-Differentiated Anxiety Intensity）

**v4.11.0 新增。** 焦虑强度必须按品类差异化，不能一刀切。

### 非敏感品类（允许更高焦虑密度）

- 普通食品（ORDINARY_FOOD）
- 日用品（GENERAL_GOODS）
- 非宣称功效化妆品

允许：

- 更强的情绪语言（烦死了 / 最怕 / 白花钱 / 看着都累 / 最后全闲置）；
- 更快的痛点切入（开头直接画面冲突 + 一句现实问题）；
- 更强的 Continuing Cost / 负面未来场景（建立在真实逻辑上）；
- 更高的 Accumulated Friction 密度。

### 敏感品类（收紧焦虑强度）

- 保健食品（HEALTH_FOOD / NUTRIENT_SUPPLEMENT_HEALTH_FOOD）
- 有功效评价的化妆品
- 医疗器械（MEDICAL_DEVICE）
- 药品（DRUG）

允许：

- 焦虑聚焦在"执行 / 选择 / 使用"等摩擦，不聚焦"身体状态"；
- 身体状态类痛点只能作为 CONTEXT_PAIN（受众上下文），不得当主卖点；
- 负面未来场景只描述"行为继续"（继续忘 / 继续闲置 / 继续纠结），不描述"身体继续"。

### COMMERCIAL_INTENSITY 联动

- **CONSERVATIVE**：焦虑强度收紧，负面未来场景只写行为，不写身体。
- **STANDARD**：非敏感品类允许正常焦虑密度。
- **AGGRESSIVE**：非敏感品类允许更强场景冲击和情绪密度；敏感品类仍按上述收紧规则。

原则：

> # 焦虑强度跟随品类天花板，永远不制造虚假疾病 / 灾难 / 稀缺。
> # 焦虑可以强，但只能强在"现实摩擦"上，不能强在"身体后果"上。

---

## 二十七、焦虑之后必须给出口

禁止全篇把用户压得很焦虑，最后不给解决逻辑。使用 **Anxiety → Relief Path** 形成情绪释放。否则容易恐吓、疲劳、反感。

产品应该扮演"把这件事变简单"，而不是"继续吓你"。

---

## 二十八、Relief Contrast

允许 **Before Friction vs After Simplicity**：

- Before：桌上一排瓶子，每天重新想。
- After：按天拿一份。

After 只能描述产品真实能改变的行为/体验，不能虚构身体结果。

**v4.11.1：After 禁止免责语气。** After 用正面表达（"按天拿一份，这件事就简单了"），禁止"它不负责让你…… / 别指望它…… / 我不指望它……"式自我设限——边界是内部审查标准，不是文案内容，不能抢走购买理由。

---

## 二十九、开头可以直接使用焦虑场景

**Douyin** 优先：画面冲突 + 一句现实问题。

```
镜头：桌上一排瓶子。
口播："这种东西我最怕的不是买贵，是最后全买回来，然后每天根本懒得弄。"
```

这比"今天给大家分享一款产品"更具有停留能力。

---

## 三十、Xiaohongshu 焦虑要变成 Decision Value

小红书不要只煽情。用户焦虑之后必须给：判断标准 / 比较维度 / 避坑方法 / 适合条件。目标："我知道怎么避免这个坑了。"

---

## 三十一、公众号焦虑升级为问题认知

公众号不要大量短促恐吓句。应该：

```
一个现实问题 → 为什么长期存在 → 我们为什么总用错方式解决 → 真正需要改变什么
```

焦虑服务认知推进。

---

## 三十二、视频号焦虑必须可转述

视频号重点："这件事确实很多家庭/普通人会遇到。"让用户能转给朋友/伴侣/家人。但不使用家庭健康恐吓。

---

## 三十三、多版本不得重复同一种焦虑

5 篇文案不要全部"怕浪费钱"。动态探索：

- Version A：执行焦虑
- Version B：选择焦虑
- Version C：时间成本
- Version D：复杂度
- Version E：后悔成本

前提：都必须被产品事实支持。

---

## 三十四、动态 Angle Discovery 加入 Pain Candidates

候选 Angle 生成时加入：Micro Pain / Repeated Friction / Loss / Decision Anxiety / Execution Anxiety / Opportunity Cost / Desired Escape。

生成 12–20 个 Angle 时，不能只从产品卖点出发，也从 **What keeps bothering the user?** 出发。最终仍必须经过 Product Relevance Gate。

---

## 三十五、External Intelligence 强化 Pain Discovery

有 WEB_SEARCH 时，研究重点不仅"用户问什么？"还要找"用户在抱怨什么？"提炼：

- REPEATED FRICTION
- COMMON CONFUSION
- BUYER REGRET
- DECISION FEAR
- USAGE COMPLAINT
- SEARCH ANXIETY

但：互联网用户抱怨只能产生 **Pain Signal**，不能自动产生 **Product Fact**。

---

## 三十六、痛点语言优先用户原生表达

如果搜索/评论出现大量"太麻烦 / 总忘 / 不知道怎么买 / 买了一堆 / 放着吃不完"，优先学习这种语言模式。不要自动翻译成"用户存在较高的决策认知成本"。

Research 可以专业。正文要像人。

---

## 三十七、禁止"五段式焦虑模板"

不要固定"痛点 → 放大 → 后果 → 产品 → CTA"。Scene 可以从：结果 / 动作 / 抱怨 / 问题 / 对话 / 失败解决 / 物件 / 选择 任意位置切入。

规则应该控制逻辑。不能暴露结构。

---

## 三十八、最终 Humanization Pass 增加

检查："这句话是用户真的会抱怨，还是营销人在替用户制造抱怨？"如果像后者：重写。焦虑越强，越需要真人语言。

## 三十九、Commercial Intensity Recovery

如果稿子"不够想买"，按顺序检查：

1. Pain 是否具体？
2. Scene 是否能看见？
3. Cost 是否真实？
4. Anxiety 是否有后果感？
5. Desired Escape 是否明确？
6. Product Bridge 是否足够近？
7. Benefit 是否说成人话？
8. Proof 是否支持？
9. Relief Contrast 是否明显？

不要第一反应：增加更多卖点。

---

## 四十、最终 Hard Gate

**PAIN & ANXIETY INTEGRITY GATE** 检查：

- Pain Reality
- Scene Specificity
- Cost Reality
- Anxiety Legitimacy
- Product Relevance
- Claim Integrity
- Relief Path

任何：虚假危险 / 无依据灾难 / 产品接不住的焦虑 = FAIL。

但是：只因为焦虑"有点强"不能自动削弱。只要真实、相关、可支撑：允许保持商业强度。

**v4.11.0 补充**：

- 焦虑强度按品类差异化（非敏感品类允许更高密度，敏感品类收紧）——但任何品类都不制造虚假疾病 / 灾难 / 稀缺。
- 痛点距离按 DIRECT_PAIN / PARTIAL_PAIN / CONTEXT_PAIN 分级：PARTIAL_PAIN 允许强表达但露出边界，CONTEXT_PAIN 只能作为受众上下文。
- COMMERCIAL_INTENSITY 档位只改变焦虑与场景的表达强度，不改变"焦虑只能作用于现实摩擦、不能作用于身体后果"的底线。

## 最终原则

> # 痛点不要只告诉用户，要让用户看到。
> # 焦虑不要凭空创造，要让真实成本浮出来。
> # 不行动也可以有成本，但这个成本必须真的存在。
> # 用户不是因为参数购买，而是因为不想继续忍受某种现实摩擦。
> # 产品出现之前，先让问题成立。
> # 产品出现以后，必须让解决路径成立。
> # 放大真实麻烦，不制造虚假危险。
> # Scene creates recognition. Cost creates tension. Anxiety creates motivation. Product relevance creates conversion.

最终目标：让用户经历——

```
"这不就是我吗？"
↓
"原来我一直在为这件事付成本。"
↓
"我确实不想再这么麻烦下去了。"
↓
"这个产品刚好解决的是我最烦的这一段。"
↓
"那我知道为什么要选它了。"
```
