# Dynamic Angle & Natural Depth Before / After 示例（references/before-after-example.md）

> **Source of Truth：Dynamic Angle Discovery Engine + Natural Depth Layer 的演示样例。** 与 `references/angle/dynamic-angle-discovery.md` + `references/angle/natural-depth.md` 的配套示例。
> 用途：展示同一任务在 v2.6（固定五版、越写越薄）与 v2.7（动态选题、自然充分）下的成品差异。**示例仅供演示表达方式，产品事实以 Sell-point Skill 为准，不得直接作为投放文案引用。**

---

## 一、任务

```text
平台：抖音
类型：IP
目的：卖货
产品：某款乌龙茶（方块紧压、一颗一泡 8-10g、兰花香奶香、半发酵焙火、15 泡打底）
人群：30-50 岁日常喝茶男性，嫌称茶麻烦
唯一第一目标：商品点击
要求：写 5 版，每版 300 字左右
```

---

## 二、Before（v2.6：固定五版、越写越薄）

> **问题B 表现**：5 版固定为"形态好奇/香气记忆/冷泡场景/避坑教学/送礼场景"五件套，只换标题和句子。
> **问题A 表现**：每版为了去 AI 感、留白、自然结束，压到 100 多字，只剩简单信息摘要，卖货逻辑被删没。

### 版本1 · 形态好奇版（约 110 字）

```text
很多人第一次看到都会问，为什么是方的。
乌龙茶里少见，手工木模压块，一颗一泡，8 到 10 克刚好一盖碗。
不用称茶，拆开就泡。
```

### 版本2 · 香气记忆版（约 105 字）

```text
兰花香，奶香，杯底有香，喝完还有香。
半发酵，焙过火，香能落进汤里。
```

### 版本3 · 冷泡场景版（约 108 字）

```text
夏天出门，500 毫升矿泉水，放四分之一颗，冷藏一夜。
冷泡香气突出。
```

### 版本4 · 避坑教学版（约 112 字）

```text
很多人以为方块茶是压碎的。
其实手工木模压块，一颗一泡，拆开是完整的。
```

### 版本5 · 送礼场景版（约 106 字）

```text
送人，棉纸包装，方块形状，有辨识度。
```

**问题诊断：**

| 问题 | 表现 |
|---|---|
| 固定五件套 | 形态/香气/冷泡/避坑/送礼，与上一批完全相同，只改标题句子 |
| 越写越薄 | 每版 100 多字，用户要求 300 字左右，结果只剩信息摘要 |
| 短句提词器 | "不用称茶，拆开就泡""兰花香，奶香，杯底有香"——产品事实一句/参数一句，无连续话流 |
| 卖货漂移 | 每版只有"一个知识点+产品名"，没有"为什么这个 IP 选它/为什么适合用户/决策信息"，漂移成内容/种草 |
| IP 过弱 | 删除产品名后感受不到谁在说，没有判断方式、选择逻辑 |
| 无心理推进 | 用户看完只记住一个卖点，没有完成购买心理变化 |

## 三、After（v2.7：动态选题、自然充分）

> **Dynamic Angle Discovery**：写正文前先生成 12-20 个候选 Angle Proposition，Angle Scoring + Semantic Distance Selection 选出 5 个真正不同、都能写充分的命题。
> **Natural Depth**：每个入选角度按 Depth Budget（1 Core Claim + 1-2 Core Proof + IP/User Decision Layer）讲到足以完成卖货心理目标，约 250-300 字。

### 版本1 · 为什么方块对嫌称茶麻烦的人反而更方便？

> Angle Proposition：把"紧压方块"翻译成"嫌称茶麻烦的人的真实决策问题"。
> Narrative Driver：用户决策驱动。

```text
你平时喝茶，是不是每次都要称克数？
嫌麻烦的人，多半最后就随便抓一把，浓了淡了全看运气。

我泡这种紧压方块，就是看中它一颗一泡。
8 到 10 克，刚好一盖碗，拆开就泡，不用称。
你说它方，它方得正好——一颗就是一次的量，出差、办公室、家里都一样。

半发酵、焙过火，快进快出，十五泡打底。
你嫌称茶麻烦，从这一颗开始泡最直接。
```

### 版本2 · 为什么这个 IP 判断乌龙茶，不先看香有多冲，而看香能不能进入茶汤？

> Angle Proposition：IP 判断角度——"香落不落水"是筛选标准。
> Narrative Driver：判断驱动。

```text
很多人挑乌龙茶，先闻香冲不冲。
我挑乌龙茶，看的是香能不能落进汤里。

浮在面上的香，闻着热闹，喝进去没味。
这一款不一样：兰花香是浮上来的，奶香是沉在汤里的。
泡开以后，汤色黄绿通透，叶底翻出来三红七绿，工艺到不到位，这两样比什么都直观。

一颗 8 到 10 克，一盖碗，快进快出，十五泡打底。
你平时喝乌龙，在意香落不落水的，可以拿一颗自己泡最直接。
```

### 版本3 · 为什么送一个长期喝熟普的人某款乌龙茶，可能并不是最稳的选择？

> Angle Proposition：送礼决策角度——不是"送茶就稳"，而是"送对人"。
> Narrative Driver：对比驱动。

```text
送礼送茶，最容易犯的错，是送一个对方不喝的类型。
对方长期喝熟普，你送一盒乌龙茶，他未必接得住——不是茶不好，是口味不对路。

乌龙茶是半发酵、焙过火，兰花香加奶香，跟熟普的醇厚是两个路子。
送之前先想清楚对方平时喝什么。
对方喝乌龙、喝岩茶，这款方块一颗一泡、棉纸包装，送出去有辨识度，也拿得出手。

送礼这件事，送对了是心意，送错了是负担。
你按对方口味选，比按"贵不贵"选更稳。
```

### 版本4 · 为什么"冷泡"不是夏天的将就，而是一种更省事的喝法？

> Angle Proposition：使用场景角度——冷泡不是将就，是省事。
> Narrative Driver：使用场景驱动。

```text
夏天喝热茶，很多人嫌麻烦，干脆不喝了。
其实乌龙茶可以冷泡：500 毫升矿泉水，放四分之一颗，冷藏一夜。
第二天拿出来，兰花香和奶香都泡出来了，比热泡更清亮。

一颗 8 到 10 克，冷泡用四分之一颗，剩下的还能泡热茶。
一颗茶，两种喝法，不浪费。

你夏天嫌热茶麻烦的，从冷泡开始，比将就着不喝强。
```

### 版本5 · 为什么"耐泡"不是参数，而是你花出去的每一分钱值不值？

> Angle Proposition：价格/价值角度——耐泡=单次成本低。
> Narrative Driver：问题驱动。

```text
买茶最怕什么？泡三泡就没味，一盒茶喝不了几天。
一算下来，单价其实不便宜。

这一款半发酵、焙过火，150 毫升盖碗一颗，快进快出，十五泡打底，能到二十泡。
一颗 8 到 10 克，泡十五泡，你算算单次成本。
耐泡不是参数，是你花出去的每一分钱，到底喝到了几泡。

你平时喝茶量大、在意耐泡的，这一颗能泡到什么时候，你自己泡一次就知道。
```

## 四、验收（v2.7 双层机制）

### Dynamic Angle 验收

| 验收项 | 结果 |
|---|---|
| Angle Proposition 非标签 | 5 版都是可展开可证明的具体命题（"为什么方块对嫌称茶麻烦的人方便"而非"方块版"） |
| Angle Scoring | 每版 Mode Fit（卖货）/Platform Fit（抖音能拍出来）/Fact Strength（有真实素材）均通过 |
| Semantic Distance | 5 版母题分散：称茶麻烦/香落水/送礼决策/冷泡场景/耐泡价值，无重复母题 |
| Previous Batch Exclusion | 与上一批固定五件套（形态/香气/冷泡/避坑/送礼）核心命题不同 |
| Example Anti-Anchoring | 角度来自当前任务真实信息动态发现，非示例默认候选 |
| 平台介入 | 每版都能拍出来（拆方块/闻杯盖/看叶底/冷泡/数泡数），有人物判断 |

### Natural Depth 验收

| 验收项 | 结果 |
|---|---|
| Depth Budget | 每版 1 Core Claim + 1-2 Core Proof + IP/User Decision Layer（如版本2"我挑乌龙茶看香落不落水"） |
| Conversational Flow | 每版连续话流（如版本1"嫌称茶麻烦→随便抓一把→一颗一泡→不用称→十五泡"），非短句提词器 |
| Mode Completion | 每版完成卖货心理变化：为什么选它/为什么适合用户/决策信息（8-10g/十五泡/可自证） |
| IP Asset | 删除产品名后仍能感受：这个人挑茶看香落水、送茶先看对方口味、算单次成本 |
| Product Relevance | 每版至少一个关键判断落到"为什么是当前 SKU"（如版本3"这款半发酵焙火跟熟普是两个路子"） |
| Soft Range 字数 | 每版约 250-300 字，在 220-330 字合理区间，深度由任务决定 |

### Batch Portfolio Check

| 检查项 | 结果 |
|---|---|
| 5 篇解决不同用户问题？ | 是（称茶麻烦/挑茶标准/送礼/夏天喝法/耐泡成本） |
| 使用不同核心命题？ | 是 |
| 有明显平台适配？ | 是（每版都能拍出来、有人物判断） |
| 存在重复母题？ | 否 |
| 每篇完成当前模式？ | 是（卖货目标保持） |
| 有些过浅？ | 否（每版都讲到足以完成决策） |
| 有些为了不同而不同？ | 否（每版都有真实用户问题支撑） |
| 都以类似节奏结束？ | 否（收口方式各异） |
| 3 篇以上结构高度一致？ | 否 |

## 五、对比要点

| 维度 | Before（v2.6） | After（v2.7） |
|---|---|---|
| 选题 | 固定五件套（形态/香气/冷泡/避坑/送礼） | 动态发现（称茶麻烦/香落水/送礼决策/冷泡省事/耐泡成本） |
| 角度形态 | 标签（"香气版"） | 命题（"为什么这个 IP 判断乌龙茶，不先看香有多冲，而看香能不能进入茶汤"） |
| 字数 | 每版 100 多字 | 每版 250-300 字（Soft Range 合理区间） |
| 话流 | 短句提词器（事实一句/参数一句） | 连续话流（因果/追问/动作/判断/场景推进） |
| 卖货 | 漂移成内容/种草 | 完成卖货心理变化（为什么选/为什么适合/决策信息） |
| IP | 删除产品名后感受不到谁在说 | 能感受判断方式（看香落水/看对方口味/算单次成本） |
| SKU 理由 | 缺失 | 每版至少一个关键判断落到"为什么是当前 SKU" |
| 心理推进 | 用户只记住一个卖点 | 用户完成购买决策所需的信息闭环 |

## 六、说明

- After 版更充分是**任务决定的深度**（Natural Depth），不是把卖点堆回去：每版仍是一个角度、一个核心命题，只是把这个命题讲到足以完成当前心理目标。
- After 版没有显式"不适合"，但版本3（送礼）通过"送熟普的人未必接得住"自然带出边界——是否出现由当前决策是否需要决定。
- 若换一批任务（"再来 5 版"），Dynamic Angle 会通过 Previous Batch Exclusion 避开本批已覆盖的角度，探索新的真实命题，而不是复现本示例。
