# CTA 路由与隐式收口库（v4.7.0）（references/craft/cta.md）

> **Source of Truth：CTA。** 来源：`ecommerce-copywriting-book-library` 的 10 收口家族（`cta-closings/cta-closings.jsonl`）与 48 CTA 模板（`cta-templates/cta-template-library.jsonl`）。
> 用法：**CTA 首先是权限问题，其次才是写作问题。** 每个任务先确定 `CTA_PERMISSION`，再决定收口方式。
> v4.7.0 核心：`CTA_PERMISSION` 只有两个值（IMPLICIT_ONLY / EXPLICIT_ALLOWED），默认 IMPLICIT_ONLY；只有命中 Closed Explicit CTA Allowlist 才允许显式。**全口径（看播/预约/成交/留资/加热）默认高级隐式收口——显式动作不属于任何口径的默认选项。** **No closing sentence is better than a forced closing sentence.**
> 本文件是 CTA 规则的唯一 Source of Truth。其他 references 只引用本文件，不得重新定义 CTA 权限条件。

## 零、CTA 安全标签

- **SAFE**：默认可用。自然互动 / 收藏 / 关注 / 转发 / 轻咨询。
- **CONDITIONAL**：只有满足事实条件时才能使用。限时 / 限量 / 折扣 / 赠品 / 库存 / 预约时间 / 价格对比。使用前必须检查事实表。
- **AVOID / LEGACY**：默认不参与自动生成。手慢无 / 炸单 / 仅剩最后 X 单 / 错过今天就没有了 / 赶紧下单 / 别犹豫 / 马上点链接（无真实依据时）。默认路由不得召回。

> 注意：**明确点击 / 下单 / 小黄车 / 去拍 不属于 SAFE。** 它们属于 Explicit CTA，只有 `CTA_PERMISSION = EXPLICIT_ALLOWED` 时才可召回（见第一节）。

## 一、CTA Permission 硬约束

**CTA is a permission problem before it is a writing problem.**

每个任务内部创建 `CTA_PERMISSION`，只有两个值：

- `IMPLICIT_ONLY`（默认）
- `EXPLICIT_ALLOWED`（仅在命中 Closed Allowlist 时）

禁止存在 `AUTO` / `MAYBE` / `PREFERRED` / `LAST_CHOICE` 等模糊状态。

### 1.1 普通 Content / Seed / Sell 默认

只要用户没有明确授权：

- Content → IMPLICIT_ONLY
- Seed → IMPLICIT_ONLY
- Sell → IMPLICIT_ONLY
- IP Content → IMPLICIT_ONLY
- IP Seed → IMPLICIT_ONLY
- IP Sell → IMPLICIT_ONLY

特别强调：

- **Sell ≠ Explicit CTA Permission**
- **热用户 ≠ Explicit CTA Permission**
- **高购买意向 ≠ Explicit CTA Permission**
- **商品卡存在 ≠ 必须念商品卡**
- **"完成决定" ≠ "告诉用户点击哪里"**
- **first_goal = purchase_decision 不自动解锁显式 CTA**（Business Goal ≠ Language Action Permission）

热用户可以提高：决策信息密度、Offer 清晰度、异议处理充分度。但不得自动提高 CTA Permission。

### 1.2 Closed Explicit CTA Allowlist（封闭白名单）

只有以下情况 `CTA_PERMISSION = EXPLICIT_ALLOWED`：

**A. 用户明确要求**（强 CTA / 明确购买口令 / 明确下单引导 / 明确点击引导 / 给我按钮文案 / 最后明确让他购买 / 明确让用户私信/预约/提交）。

**B. 任务本身是**：直播成交阶段 / 直播最后逼单·成交收口 / 商品卡 Button / 广告 CTA Button / Landing Page Button / 表单提交 Button / 明确私域动作指令。

除此之外：**Explicit CTA = prohibited。**

这是 Closed Allowlist。Agent 不得自行增加许可原因。

### 1.3 Weak Explicit 仍然属于 Explicit

以下虽然语气轻，仍然是 Explicit：

- 想试的下面就是
- 可以去看看
- 合适的话拍一盒
- 链接在下面
- 有需要的自己去看
- 想喝可以下单
- 小黄车里有
- 商品卡可以看看
- 进店看看

判断标准：**只要明确告诉用户 去哪里 / 点击什么 / 执行什么购买动作，就是 Explicit CTA。** 语气温和不改变分类。

### 1.4 用户阶段对 CTA 的影响

- 冷用户：弱/无 CTA，先给价值。
- 温用户：中强度，收藏/关注/轻咨询。
- 热用户：提高决策信息密度、Offer 清晰度、异议处理充分度；**不改变 CTA Permission。**

## 二、CTA 分口径原则（全口径默认高级隐式收口）

凡模板含多类别 CTA，产出时必须按用户明确目标（goal）选定**一个**口径执行，禁止用模板默认类别覆盖用户目标。

**全口径硬约束（v4.7.0）：所有口径（看播 / 预约 / 成交 / 留资 / 加热）默认收口方式 = NATURAL_STOP 或 IMPLICIT_CLOSE。显式动作（进直播间 / 点预约 / 点购物车 / 下单 / 去拍 / 去看看 / 点我头像 / 点下方）不属于任何口径的默认选项。** 只有命中 Closed Explicit CTA Allowlist（第一节 1.2）才允许显式。

平台组件（头像 / 商品卡 / 预约组件 / 表单 / 搜索入口 / 投放组件）承担动作；正文负责价值、判断与信息缺口。

| 用户目标 | 收口口径（默认隐式） | 示例（隐式） |
|---|---|---|
| 进直播间看播/观看 | 隐式续接 / 无指令缺口 / 抽象价值预告；不写目的地，不收时间限定词 | 后段从哪一泡开始变淡，还得看同一颗茶继续往下走 |
| 预约（预告开播时间、到点提醒） | 价值预告 + 判断留白；动作由预约组件承接 | 这一场讲透怎么挑，听完这一场，挑茶那点门道就齐了 |
| 成交/下单 | 完成购买判断；动作由商品组件承接 | 一颗对应一盖碗，是否适合日常喝，按自己的茶桌习惯决定 |
| 留资 | 形成明确适配问题或下一步条件；动作由表单组件承接 | 人数、预算和使用频率不同，具体方案要按实际情况再定 |
| 加热（投放后台） | 播放/互动/涨粉，文案口径与后台目标一致 | 加热视频内配互动型 CTA（点赞/关注） |

**看播口径免时间限定（通用）**：直播引流素材只在开播时被刷到，看播稿不写今晚/明晚/几点，时间锚点仅预约口径使用。

**口径 ≠ 显式许可**：口径描述的是"用户目标 → 收口机制"，不授予显式动作权限。任何口径下，正文收口默认走隐式家族（第四节）；显式动作词只出现在 Closed Allowlist 场景（第一节 1.2）。

## 二·五、高级隐式收口定义与质检（v4.7.0）

**高级隐式收口 = 承接本版核心观点的自然收尾，不命令动作、不写目的地、不报时间、不描述直播间行为。** 它不是"值不值自己判断"式万能句，而是与正文同一人格、同一理由的收束。

### 高级隐式收口六项质检（逐条通过才算合格）

1. **零动作指令**：不含 进直播间 / 点预约 / 点购物车 / 下单 / 去拍 / 去看看 / 点我头像 / 点下方 / 扣字 等动作词。
2. **零目的地**：不含 直播间 / 小黄车 / 商品卡 / 链接 / 下方 / 头像 等承接入口词。
3. **零时间限定**：不含 今晚 / 明晚 / 几点 / 稍后 / 马上 等时间锚点（预约口径由组件承接时间）。
4. **零直播间行为预告**：不含 开播我讲 / 现场拆饼 / 直播间等你 / 我泡给你看 等对直播间实时行为或动作镜头的描述。
5. **承接本版核心观点**：收口句必须回扣本版正文的具体卖点 / 理由 / 判断（如正文讲十五泡 → 收在"自己泡一泡，眼见为实"），禁止与正文脱节的万能句。
6. **同批次句式指纹不重复**：核心动词、价值理由词、收尾人称、句式结构不得与同批次其他版雷同（见 5.3）。

### 高级 vs 低质隐式对照

| 低质隐式（万能句，禁止） | 高级隐式（承接观点，合格） |
|---|---|
| 值不值，自己判断 | 十五泡到底是不是真的，自己泡一泡，眼见为实 |
| 合不合适，自己最清楚 | 三条标准记好了，按这三条去对，好茶坏茶，自己分得清 |
| 想了解的进直播间来看 | 四四方方一颗，拆开就是一杯，见过就记住了 |
| 下方预约点一下，开播我提醒你 | 这一场讲透怎么挑，听完这一场，挑茶那点门道就齐了 |
| 值不值得，自己心里有数 / 合不合适，你自己掂量 | 四十天三伏，靠这一壶，能舒坦不少（回扣本版场景） |

> 判断标准：**把收口句删掉再接上正文，是否仍是同一个人在说话？** 是 → 高级；不是（突然变营销腔/万能句）→ 重写。

### 判断留白机械句（v4.19.0 新增，禁止）

**判断留白机械句 = 把判断权空泛地交还用户，但不携带本版任何具体内容的万能收口。** 它看似"高级隐式"，实则换任何产品、任何正文都能用，是 AI 模板痕迹最重的收口。

| 机械句（禁止） | 识别特征 |
|---|---|
| 值不值得，自己判断 / 自己心里有数 | 只给"判断"动作，不给判断标准 |
| 合不合适，你自己定 / 你自己掂量 | 只回抛"选择权"，不携带本版场景 |
| 值不值，自己最清楚 | "值不值"是空泛价值词，任何产品都成立 |
| 谁喝谁知道 / 一试便知 / 一喝就知道 | 句末强化句，观点已成立后追加的空泛强调（见 anti-patternization.md 十·一） |

**互换性测试（Interchangeability Test）**：把收口句里的产品/场景/标准词全部替换成另一个产品，若句子依然成立 → 机械句，重写。收口必须证明"只属于这一篇"——回扣本版正文的具体卖点、具体标准、具体场景。

**合格对照**：
- 机械：值不值得，自己判断 → 合格：十五泡到底是不是真的，自己泡一泡，眼见为实（回扣"十五泡"）
- 机械：合不合适，你自己掂量 → 合格：四十天三伏，靠这一壶，能舒坦不少（回扣"三伏天冷泡"场景）
- 机械：谁喝谁知道 → 合格：删掉，正文已把"冷泡清爽回甘"讲透，自然结束（Natural Stop）

## 三、直播引流素材边界原则

千川引流直播间的素材文案，**不得描述直播间的任何具体行为或动作**。

- **禁止**描述实时现场行为："此刻直播间正在拆样品""主播正在……"。
- **禁止**描述预告中的具体动作镜头："我现场演示拆饼/冲泡/看叶底""现场给你泡一杯"。
- **允许**只做**抽象价值预告**：主题（专注讲什么）、能获得什么（讲解/答疑/判断方法）、时间或稀缺线索（"本场就讲这一场"）。

现场感由直播间本身呈现；素材负责"给一个进来看的理由"，直播间负责"兑现这个理由"。

## 四、隐式收口机制资产库（16 个家族）

收口家族决定"这句怎么收"。**Closing Family 仅当 Closing Strategy = IMPLICIT_CLOSE 时才需要内部选择；Closing Strategy = NATURAL_STOP 时不分配任何 Closing Family。**

> 本表只描述**机制**（这句收口在心理上做什么）。示例方向是机制示意，不是可直接照抄的成品句；产出时必须按当前正文自然转译。

| 家族 | 机制（心理上做什么） | 适用场景 |
|---|---|---|
| **no_command_end 无指令留白** | 用判断句或画面收尾，不给出任何指令 | 内容型 / 种草型 / IP型 |
| **choice_helper 选型助手** | 把选择权交还用户，按用户自己的场景决定 | 种草型 / 卖货型 |
| **verification_task 验货任务** | 把判断权交给用户亲手验证 | 种草型 / 卖货型 |
| **echo_close 首尾呼应** | 回到开头场景/问题形成闭环 | 所有类型 |
| **process_continuation 过程续接** | 已开始的动作留到未走完的节点 | 演示型 / 教程型 |
| **answer_destination 答案落点** | 判断问题的答案留到后续揭晓 | 系列内容 / 引流型 |
| **value_preview 价值预告** | 抽象价值预告（能听懂/能看明白） | 引流型 / 直播预热 |
| **knowledge_unlock 知识解锁** | 只讲一部分，剩余留到后续 | 系列内容 / 涨粉型 |
| **memory_suspense 记忆悬念** | 用反常/前后落差做记忆点 | 所有类型 |
| **question_echo 问题回抛** | 把判断问题抛回给用户，不做包办结论 | 内容型 / 种草型 |
| **scene_leave 场景留白** | 画面停在生活场景，让用户自己代入 | 内容型 / IP型 |
| **contrast_close 反差收束** | 用反差/转折句收尾，制造回味 | 所有类型 |
| **habit_seed 习惯种子** | 把使用种进日常习惯，暗示长期价值 | 内容型 / 种草型 |
| **story_open 故事留口** | 留一个未讲完的故事尾巴 | IP型 / 内容型 |
| **taste_invite 味觉邀请** | 用想象/回忆邀请用户感受味道 | 种草型 / 卖货型 |
| engagement_close 互动/福利 | 评论区/点赞/抽奖等可兑现互动 | 仅明确要求互动时 |

### 家族句式变体库（机制示意，非可直接照抄句）

同一家族在不同批次使用时，**必须更换句式变体**，不得沿用上次句式。每个家族至少 3 个变体方向：

| 家族 | 变体方向A | 变体方向B | 变体方向C |
|---|---|---|---|
| no_command_end | 原料这一关过了，剩下的就看自己的口味了 | 茶汤还冒着热气，人已经安静下来了 | 该说的都说了 |
| choice_helper | 如果你也看重原料品质，这款可以放进你的候选清单 | 看你是自己喝还是送人，再决定要不要选这一款 | 平时喝得浓还是喝得淡，按这个标准对号入座 |
| verification_task | 是不是真的好，自己拆一盒泡一次 | 按这几招过一遍，是真是假，泡一杯就有答案 | 好与不好，拆一颗泡开，看汤色翻叶底 |
| echo_close | 回到开头那个问题，这一颗就是答案 | 开头那杯茶，喝到这儿，你该明白它为什么值得了 | 开头说的那口香，现在你闻到了 |
| process_continuation | 按这个节奏喝上一阵，再回头看合不合你的口 | 后面还有几泡变化，泡到第八泡再回来看汤色 | 这泡茶的故事，还没讲到结尾 |
| answer_destination | 到底怎么挑，多对比几家你就有答案了 | 答案，藏在你自己喝过的那些茶里 | 喝得多了，答案自然就出来了 |
| value_preview | 进去能听懂、能看明白，不会浪费你时间 | 这一场，值得你花几分钟 | 看完这一条，你会比多数人更懂怎么选 |
| knowledge_unlock | 剩下几个判断维度，下次接着说 | 关于工艺的门道，还有一半没讲 | 想听完整的，先记住今天这一条 |
| memory_suspense | 它和市面上那些的区别，恰恰在最不起眼的地方 | 看着普通，喝过的人才懂 | 这一口为什么值得记住，你喝过就懂 |
| question_echo | 你平时选茶，先看什么？ | 如果是你，你会怎么选？ | 你上一次认真喝一泡茶，是什么时候？ |
| scene_leave | 茶香还在，人已经走神了 | 窗外的雨声，和杯里的茶香，刚好 | 那口香，会跟着你到明天 |
| contrast_close | 贵的不一定对，对的不一定贵 | 看着简单，喝过才知道不简单 | 喝得多了，自然知道哪一口才是你的 |
| habit_seed | 习惯这东西，是一泡一泡养出来的 | 一天一泡，慢慢就成了习惯 | 喝得顺了，慢慢就成了日常 |
| story_open | 这茶的故事，还长着呢 | 做这茶的人，也有自己的故事 | 关于它，还有一半没讲 |
| taste_invite | 你有多久没喝到这种香了？ | 想象一下，兰花香和奶香一起入口 | 爱喝茶的人，闻到这香就走不动 |

> 变体库同样受"判断留白机械句"约束（见二·五）：变体必须携带具体标准/场景/物件，禁止"自己判断/自己心里有数/你自己定/你自己掂量/值不值/合不合适"式空泛判断句。

### 选择优先级（从高到低）

1. no_command_end（最自然，像真人说话结束）
2. choice_helper（最种草，把选择权还给用户）
3. verification_task（最有说服力，让用户自己验证）
4. echo_close（最完整，首尾呼应有闭环）
5. question_echo（最互动，把问题抛回给用户）
6. scene_leave（最有画面，场景留白代入感强）
7. contrast_close（最有回味，反差制造记忆点）
8. 其他按场景选择

规则：
- 种草型内容：只从隐式家族中选择，禁止 engagement_close
- 卖货型内容：优先决策完成感，隐式收口备选（choice_helper / verification_task / contrast_close）
- 收口句必须承接本版核心观点
- 同批次各版收口的动作词、价值理由、收尾人称、句式口径不得重复（Creative Variation 适用）
- **A/B 例外**：A/B 单变量测试只改变被测试变量（如收口方式），正文、证据、钩子保持一致；此时批量差异化规则让位于 A/B 单变量原则。

## 五、收口家族轮换与配额（拒绝单一重复）

**三重防重复机制，从"家族"到"句式"层层拦截。**

### 5.1 单批次配额

- 同一批次内，即使家族不同，收口句的核心动词、价值理由词、收尾人称、句式结构也不得雷同（见 5.3 句式指纹）。
- **不要求每篇必须拥有 Ending Module / Closing Family。** 多版可以是 NATURAL_STOP / NATURAL_STOP / IMPLICIT_A / IMPLICIT_B / NATURAL_STOP，完全合法。

### 5.2 跨批次轮换（Memory-Gated）

- **只有存在 `MEMORY` capability，或用户当前上下文明确提供 Content History 时，才能运行 Cross-Batch Closing Rotation。**
- 否则：只检查 Current Batch，不得假装记得上一批用了什么，不得虚构使用次数。
- 原则：**No memory capability → no cross-session memory claim.**

### 5.3 句式指纹防重

收口句生成后，逐项检查指纹是否与同批次其他收口句冲突：

| 指纹维度 | 检查项 | 冲突示例 |
|---|---|---|
| 核心动词 | "看看/试试/判断/心里有数/自己"等是否重复 | 两版都用"自己判断" |
| 价值理由词 | "正宗/值不值/合不合适/对/正"等是否重复 | 两版都收在"值不值"上 |
| 收尾人称 | "你/自己/心里/我"等是否重复 | 两版都以"你心里有数"收尾 |
| 句式结构 | "……，自己……""回到开头……""……就知道了"等是否重复 | 两版都用"……就知道了" |

**任一指纹维度冲突 → 必须换家族或换变体。**

### 5.4 家族使用计数（Memory-Gated）

- 有 MEMORY 或 Content History 时：记录各家族使用情况（批次、版本、句式），未使用过的家族优先。
- 无 MEMORY 且无 History 时：不累计、不声称历史使用次数，只做 Current Batch QA。

## 六、隐式收口自然化原则

模板的 `cta` 与 `example` 是**选型与结构参考**，不是可直接照抄的收口句。产出时须转为自然话术，**优先选择隐式机制**：

- **业务目标不等于口播词**：看播、成交、留资、搜索承接、种草、品牌认知都是后台目标，不是正文必填词。头像、商品卡、表单、搜索入口和投放组件可以承担动作；正文优先用信息缺口、购买判断、适配问题、知识答案、记忆点或无指令结尾。
- **顺着证据收束**：把模板的 `goal` 翻译成本版核心判断的自然收束。只有当承接入口确实不明显且 `CTA_PERMISSION = EXPLICIT_ALLOWED` 时，才补充一句显式引导。
- **组件转译（仅显式时需要）**：内部组件名（购物车/商品卡/预约/表单）转译成自然口语，不能当口播词硬念。"点击下方购物车"是后台组件标签，不是真人说出口的话。
- **收口差异化**：同批次各版收口的家族、角度、句式、语气不得重复；跨批次按第五节轮换机制执行（Creative Variation 适用；A/B 单变量测试例外，只改变被测试变量）。
- **不撒谎不越界**：不承诺做不到的福利/时效；直播引流只做抽象价值预告。

**种草文案收口示例对照：**

生硬（显式）：`想喝的点击下方小黄车，直接去拍。`（Explicit，默认禁止）

自然（隐式·判断收束）：`原料这一关过了，剩下的就看自己适不适合了。`

自然（隐式·选型助手）：`如果你也看重原料品质，这款可以放进你的候选清单。`

自然（隐式·验货任务）：`是不是真的好，自己试一盒就知道了。`

自然（隐式·味觉邀请）：`你有多久没喝到这种香了？`

**卖货文案收口示例对照：**

生硬（显式）：`赶紧下单，手慢无！`（Explicit + AVOID，默认禁止）

自然（隐式·决策完成）：`该说的都说了，剩下的按自己的茶桌习惯决定。`

自然（隐式·反差收束）：`贵的不一定对，对的不一定贵。`

## 七、隐式收口三层翻译（目的 → 平台 → 人格）

收口不是直接从商业目标生成的指令。必须经过三层翻译，否则会出现"正文像真人、收尾突然变营销腔"。

**第一层 · 目的**：先确定内容目的（内容/种草/卖货），选择对应的隐式收口家族（见第四节选择优先级）。

**第二层 · 平台**：按平台消费心智翻译：
- 抖音：判断 + 现场感（"原料这一关过了，剩下的就看自己的口味了。"）
- 小红书：帮用户做选择（"如果你刚好在这几款里纠结，可以按这个标准再对照一下。"）
- 公众号：理性判断（"如果你的需求和上面这几条一致，再去看看产品也不迟。"）
- 视频号：保护长期信用（"真有这个需求的，按自己的情况再考虑，不适合你的，也不用因为我说了就买。"）

**第三层 · 人格**：CTA 必须与正文是同一个人。删掉 CTA 再接上时，仍是同一个人在说话。克制型 IP 用克制收口，热情型 IP 用热情收口，禁止正文与 CTA 人格断裂。

**三层翻译检查**：
- 目的是否单一？（禁止一个 CTA 同时追看播+成交+留资）
- 平台是否原生？（同一句 CTA 换平台仍成立 = 未完成平台层翻译）
- 人格是否一致？（删掉 CTA 再接上是否还是同一个人？）

## 八、平台 × 目的 × 家族映射（防跨内容重复）

不同平台 × 目的组合，优先使用不同家族，避免同一账号跨内容收口雷同。

| 平台 | 内容型 | 种草型 | 卖货型 |
|---|---|---|---|
| 抖音 | scene_leave / memory_suspense / question_echo | verification_task / taste_invite / no_command_end | choice_helper / contrast_close / process_continuation |
| 小红书 | choice_helper / question_echo / habit_seed | verification_task / taste_invite / choice_helper | choice_helper / verification_task / answer_destination |
| 公众号 | answer_destination / contrast_close / knowledge_unlock | knowledge_unlock / answer_destination / contrast_close | contrast_close / answer_destination / no_command_end |
| 视频号 | no_command_end / story_open / habit_seed | habit_seed / story_open / echo_close | no_command_end / habit_seed / echo_close |

**用法**：先查本表锁定该平台×目的的首选家族池，再按第五节轮换机制从池内选择。跨批次避开上一批次已用家族仅在 MEMORY 或 Content History 存在时执行。

## 十、Decision Continuation CTA（决策延续式 CTA）

CTA 不再是"文案末尾必须有一句按钮提醒"。**CTA 的本质是：当前用户决策的自然下一步。**

| 正文核心理由 | CTA 承接（顺着理由） | 禁止（统一模板） |
|---|---|---|
| "方块一颗一泡，适合嫌称茶麻烦的人" | "你平时喝茶就嫌称克数麻烦，可以从这个试试" | "想试的点下面" |
| 正文讲香 | "真正在意香落不落水的，拿一颗自己泡最直接" | "链接在下面" |
| 正文讲送礼 | "对方平时喝乌龙，再考虑这款会更稳" | "去拍就行" |

**不同内容的 CTA 理由应该不同。** CTA 必须承接本版正文的具体理由，不能与正文脱节。同批次各版 CTA 的理由、动作词、人称不得重复（Creative Variation 适用；A/B 单变量测试例外，只改变被测试变量）。

> 承接列中的"可以从这个试试"等属于弱显式，默认仍按 Explicit 对待；只有 `CTA_PERMISSION = EXPLICIT_ALLOWED` 时才可输出。

## 十一、并非每篇卖货都必须显式 CTA

当模式是 IP 卖货，必须完成：

1. 为什么这个 IP 选择这个 SKU
2. 用户为什么值得考虑
3. 用户是否具备完成购买决定的信息

但**不一定必须写**"点击/下单/链接/下面/去拍"。如果产品承接在平台视觉、商品卡、直播间本身已经明确，可以自然结束。

**"卖货必须有决策信息" ≠ "卖货必须有一句按钮提醒"。** 显式动作词不是必填项。当正文已经完成购买判断、平台组件已经承担动作时，允许无指令收尾。普通 Sell 默认没有显式 CTA 权限；只有命中 Explicit Allowlist 才能显式。

## 十二、Natural Stop（自然收尾）

**最高原则：No closing sentence is better than a forced closing sentence.**

写完以后先删除最后一句。如果删除后：

- Purpose 仍完成
- 决策仍完整
- 内容仍自然

则删除。不强制追加尾句。

Closing Strategy 只允许三种：

1. `NATURAL_STOP`（默认优先）
2. `IMPLICIT_CLOSE`
3. `EXPLICIT_CTA`（仅当 `CTA_PERMISSION = EXPLICIT_ALLOWED`）

默认优先级：NATURAL_STOP → IMPLICIT_CLOSE → EXPLICIT_CTA（仅当被允许）。

- 想试的下面就是 / 链接在下面 / 去拍就行 / 点进来看看 / 小黄车里有 / 进店看看
- 赶紧下单 / 别犹豫 / 手慢无 / 仅剩最后 X 单 / 错过今天就没有了

## 使用红线

- 禁止生硬命令式："赶紧下单""别犹豫""马上点链接""手慢无"。
- 禁止虚假紧迫/稀缺："仅剩最后 X 单""错过今天就没有了"（无真实依据时）。
- 禁止重复口号式 CTA：同一批次各版收口动作词与理由不得重复；跨批次轮换仅在 MEMORY 或 Content History 存在时执行（Creative Variation 适用；A/B 单变量测试例外）。
- 禁止家族滥用：同一家族在同一批次出现 2 次以上、或连续批次沿用同一家族同一变体，视为违规。
- 种草不逼单，卖货不虚假稀缺，IP 不透支信用。
- 显式 CTA 必须命中 Closed Allowlist；Agent 不得自行增加许可原因。
