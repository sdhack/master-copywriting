# IP 真人感与自然度（references/ip-naturalness.md）

> **Source of Truth：IP 真人感与自然度。** 主 SKILL.md 只保留简要调用；本文件是 IP 真人感与自然度的唯一 Source of Truth。
> 适用范围：**抖音 × IP × 卖货** 优先执行；可泛化原则同时应用于其他 IP 内容（IP 种草 / IP 内容 / 各平台 IP 表达）。
> 目标：解决 AI 感、模块拼接感、产品说明书感、IP 缺失、口播不自然、多版本同质化。
> 总纲：**真人感 > 模板完整；人的判断 > 产品资料；一条讲透 > 卖点堆满；自然连贯 > 结构痕迹；长期信任 > 一次话术刺激。**

---

## 一、IP 卖货首先写"人"，不是首先写"产品"

当模式为【IP × 卖货】，生成前必须内部回答：

- 这个 IP 为什么有资格谈这个产品？
- 这个 IP 平时看重什么？
- 这个 IP 选择产品的标准是什么？
- 这款产品为什么符合他的标准？
- 用户看完会记住这个 IP 什么判断？
- 去掉产品名以后，这段话是否依然像这个 IP 会说的话？

**IP 卖货核心结构优先：**

```text
人的判断 → 选择标准 → 产品符合标准的证据 → 用户是否适合 → 成交
```

**避免：**

```text
钩子 → 产品百科 → 卖点堆叠 → CTA
```

IP 存在感不能只通过增加"我"字完成。真正的 IP 感来自：**判断、取舍、标准、偏好、经验、说话方式、对什么东西不认同。**

如果缺乏用户提供的真实经历，不得虚构经历，但可以表达真实可成立的：**判断标准、产品观察和选择逻辑。**

---

## 二、一条视频只讲一个核心话题

禁止为了体现产品价值，把资料库中的所有卖点塞进一条文案。

每条短视频：**1 个核心卖点 + 最多 2 个辅助信息。** 其余卖点主动删除。

例如：

- **形态角度**：只围绕"为什么是方块 → 这种形态对喝茶有什么实际意义 → IP 为什么喜欢"。
- **香气角度**：只围绕"香气是什么感觉 → IP 怎么判断茶香好不好 → 产品如何体现"。
- **送礼角度**：只围绕"IP 怎么看送茶 → 什么茶适合什么人 → 为什么选择这款"。

**禁止每版都重复**：工艺、香气、泡法、汤色、叶底、耐泡、产量、售后、CTA 全塞进一条。

---

## 三、多版本必须"换思路"，不能只"换开头"

Creative Variation 模式下，不同版本必须至少改变以下三项中的两项：

- 用户进入场景
- 核心观点
- 核心卖点
- 产品出现时机
- 主体故事
- 证据类型
- 用户购买理由

**禁止**：不同钩子 + 相同产品说明 + 相同 CTA 的伪多版本。

判断标准：**删除每版第一段以后，如果剩余正文高度相似，则视为多版本失败，必须重写。**

---

## 四、真人口播优先遵循"话题自然生长"

禁止把结构直接显露在语言里。不要让正文呈现明显的：钩子模块 → 产品模块 → 证据模块 → CTA 模块。

真人口播应该表现为：**一句话引出下一句话。**

优先使用以下之一推动内容：

- 一个具体动作
- 一个真实观察
- 一个自然问题
- 一个判断
- 一个小反应
- 一个生活场景

例如：

- 不要："产品采用传统工艺，具有兰花香，耐泡度高。"
- 优先："你先别急着喝，水刚进去的时候闻一下，这个香是慢慢起来的。对我来说，乌龙茶好不好喝，香得高不高反而不是第一位，我更在意它落不落到水里。"

语言必须有**人正在说话的感觉**，而不是**人正在背产品资料的感觉**。

---

## 五、真人允许"不完整"

AI 倾向于把一条文案讲得面面俱到。真人不会。因此：**完整度让位于自然度。**

允许：

- 不讲所有卖点
- 不交代全部参数
- 不总结
- 不升华
- 不使用完整营销闭环
- 某些内容没有明显金句

只要**第一目标完成**。尤其短视频中：**一个问题讲透，比六个卖点讲一遍更重要。**

---

## 六、"产品介绍腔"检测

生成后检查连续两句以上是否都在：

- 罗列参数
- 罗列工艺
- 罗列卖点
- 罗列功效
- 罗列产品信息

如果是，必须加入以下之一打断：

- 人的判断
- 场景
- 动作
- 取舍
- 用户问题

**不能出现超过两句话连续像产品说明书。**

---

## 七、"真人说话"检测

逐段检查：**一个真实经营者、创作者或店主，面对镜头会不会这么说？**

如果一句话明显属于：详情页、品牌宣传册、AI 总结、营销教科书、主播标准话术，必须口语化重写。

**特别警惕以下高频机械营销表达**（除非符合该 IP 长期真实表达习惯）：

- 品质自己看得见
- 产量有限
- 值得入手
- 性价比很高
- 轻松满足
- 给你带来
- 不容错过
- 运费险安排上
- 带一单回去
- 打开新世界
- 更绝
- 妥妥的
- 闭眼入

---

## 八、CTA 必须继承 IP 语气

不要正文像懂茶的人，结尾突然变成标准带货主播。CTA 必须满足：**删掉 CTA 以后，重新接上它时仍然是同一个人在说话。**

例如克制型 IP 可以：

> 没喝过这种方块乌龙茶的，可以从这一泡试试，我们家的就在下面。

而不是强制：

> 左下角带一单，赶紧尝尝。

IP 卖货可以直接成交，但**成交语言必须人格一致。**

---

## 九、事实类型进一步拆开

食品、茶叶等商业文案必须严格区分四类事实：

| 类型 | 定义 | 例子 |
|---|---|---|
| 品类事实 | 关于"某款乌龙茶"这个品类的一般事实 | 乌龙茶、紧压方块、半发酵 |
| SKU 事实 | 关于当前这款某款乌龙茶的具体事实 | 老师傅手作、100克/盒、棉纸包装 |
| IP 体验 | IP 本人真实使用或经营经历 | 用户明确提供的个人感受 |
| 推导 | 从事实合理推导出的使用价值 | 一颗一泡 → 携带方便 |

**禁止：**

- 把【品类事实】自动写成【当前 SKU 事实】。
- 把【常见描述】自动写成【IP 亲身体验】。
- 把【工艺】自动推导成【身体功效】。

## 十、食品饮品特别限制

没有明确证据时，禁止自动生成：

- 温和不刺激
- 不伤胃
- 暖胃
- 养胃
- 降火
- 提神效果承诺
- 长辈都适合
- 孕妇适合
- 儿童适合
- 一定不会苦涩
- 一定多少泡
- 喝一天
- 一杯多少钱
- 复购率
- 用户评价

类似"焙过火 → 所以温和不刺激"这种**跨层推导禁止**。

---

## 十一、参数只在"对用户有意义"时出现

不要为了专业感自动写"150ml盖碗、100℃、一颗投进去……"，除非这一条主题就是泡法。

- 形态好奇版：参数应删除。
- 送礼版：冲泡参数应删除。
- 香气版：只保留真正帮助用户体验香气的信息。

原则：**参数不能证明当前核心观点，就不要出现。**

---

## 十二、连贯性优先于结构完整

生成后进行一次"去模块化重写"。检查每句话：**为什么下一句会接在这一句后面？**

如果只能回答"因为模板下一步该讲这个"，则连接失败。

必须使用以下之一重新建立自然连接：

- 因果
- 反应
- 问题
- 转折
- 动作
- 判断

最终文案应该可以**一口气读下来**，而不是**每一段都正确，但彼此像拼上去的**。

---

## 十三、人格动作（IP 内容必做）

IP 不是多写"我"。每篇 IP 内容至少出现一个：

- 判断
- 选择
- 取舍
- 拒绝
- 坚持
- 改变
- 偏好
- 标准

例如：

- 我不太看重……
- 我更在意……
- 这种东西我一般不会推荐……
- 我选这类产品先看……
- 这个问题我和很多人看法不一样……

这些比"我做了很多年……"更能建立 IP。但禁止虚构经历。

## 十四、IP 存在感不能只靠"我判断"

IP 内容必须有人格资产，但人格资产可以通过多种方式表现，**禁止把 IP 感固定写成"我选 XX 看……/我判断 XX……/我的标准是……"**。这些句式可以使用，但不得成为默认句式。

IP 人格资产的多种表现方式：

| 表现方式 | 示例 |
|---|---|
| 选择 | 同类里我会先看这一项 |
| 动作 | 你看，我把这一颗拆开 |
| 取舍 | 我宁可少一个卖点，也不会…… |
| 拒绝 | 这种说法我一般不接 |
| 比较 | 和那种抽湿的比，这个焙过火 |
| 现场演示 | 水冲下去，你闻一下这个香 |
| 问题回答 | 很多人第一次看到都会问，为什么是方的 |
| 产品选择顺序 | 我挑乌龙茶，先看汤色，再看叶底 |
| 什么信息不讲 | 我不跟你讲那些虚的，就看泡出来什么样 |
| 如何处理用户疑问 | 你问耐不耐泡，泡到第十五泡你自己看 |

**核心原则**：IP 是"这个人的决策方式"，不是"每篇都有一句我的标准"。

同一个 IP 可以长期稳定：价值观、判断原则、语气、对用户态度、专业边界；但不应该长期重复：同样开场、同样转折、同样句型、同样 CTA、同样"不适合"、同样结构。

**即：人格一致 ≠ 文案形式一致。** Set-Level QA 负责打散模板化重复。

## 十五、禁止"专业克制模板化"

当前 AI 容易形成"前面先强判断，后面再补免责声明"：

> 看叶底就能辨好坏。不过单看叶底也不够。

这种"先绝对，再免责声明"不自然。改成**边界直接进入原始判断**：

> 我自己看这类茶，叶底会看，但一般会和汤色、香气一起判断。

即：**不要"先绝对，再免责声明"**。边界是判断的一部分，不是判断之后的补丁。Professional Humility 的"不绝对"应该体现在判断的措辞里，而不是体现在判断之后追加一句"不过……"。

## 十六、专业表演感检测（IP 内容）

IP 内容尤其容易出现"为了证明自己专业，不停解释知识"。

规则：当 IP 已经给出一个明确判断后，最多用 **2 个证据**证明。
优先证据顺序：
1. 真实动作 → 2. 现场观察 → 3. 选择标准 → 4. 真实对比 → 5. 必要知识解释

不要优先长篇科普。如果一段让用户明显感觉"这个人在努力证明自己懂行"，删除至少 30% 的专业解释。

## 十七、普通内容不要强行 IP 化

当模式是普通内容时，不要为了真人感强塞"我的经历/我的标准/我的朋友/我的客户/我用了多久"。

普通内容的真人感来自：**自然表达 + 真实场景 + 清楚判断 + 具体信息。** 不是强行人设化。

## 十八、金句限额

每篇最多 **1 句** 对仗 / 升华 / 高度概括 / "可以摘出来发朋友圈"的句子。如果正文已经有鲜明判断，结尾不再强行升华。

禁止每篇都写成"X 不是 A，而是 B""真正的 X……""X 出去是 A，回来是 B"。真人不会每条内容都留下名言。

## 十九、自然结束检测

完成正文后，删除最后一句。如果内容已经自然成立，检查最后一句是否只是为了总结/金句/升华/强行互动/强行成交而存在。如果是：删除。不是所有内容都必须有明显的"结尾"。

## 二十、朗读测试

短视频最终稿必须进行口头朗读模拟。出现以下情况必须改：

- 一口气说不完
- 书面词太多
- 连续解释太长
- 逻辑虽然对但说出来别扭

但真人感不等于故意语病 / 故意错别字 / 大量"啊、呢、嘛" / 家人们 / 宝子 / 哈哈哈。自然即可。

## 二十一、抖音 IP 卖货建议默认结构

在没有更适合结构时，优先：

```text
真实观察 / 用户问题
  ↓
IP 的一句判断
  ↓
为什么这么判断
  ↓
产品里的一个具体证据
  ↓
用户适合 / 不适合
  ↓
自然成交
```

注意：这是**思考结构**，不得直接形成模板化语言。

## 二十二、最终真人感自检

生成后内部逐项检查：

### A. 换人测试

这篇文案换一个同行说是否完全成立？是 → IP 感不足。

### B. 删除产品测试

删除产品名称以后，是否还能感受到这个 IP 的判断、性格、标准？完全没有 → IP 失败。

### C. 朗读测试

真实的人能否不别扭地一口气说出来？不能 → 重写。

### D. 说明书测试

是否连续出现大量工艺 + 参数 + 香气 + 汤色 + 叶底 + 耐泡？是 → 删掉至少一半。

### E. 同质化测试

多版本去掉开头以后是否基本一样？是 → 重新做角度。

### F. AI 句测试

是否存在"打开新世界""品质自己看得见""值得入手""产量有限""运费险安排上""左下角带一单"等高频机械营销表达？若不是 IP 真实语言习惯 → 改成人话。

---

## 二十三、输出层禁止暴露内部标签

最终用户只要求文案时，禁止输出：

- SAFE / CONDITIONAL
- 钩子类型
- 结构名称（AIDA / SCQA / PAS 等）
- 评分
- 路由
- 内部判断
- 事实等级

这些属于内部工作过程。最终只输出：**可以直接发布、直接口播的成品。** 除非用户明确要求查看分析。

## 二十四、事实边界约束（v2.5 起，IP 内容必读）

> 完整规则见 `expression-authority.md`。IP 内容在"真人感"之上叠加两道事实边界：**IP Fact Firewall** 与 **Professional Humility**。

### 24.1 IP Fact Firewall（IP 事实防火墙）

真人感不得通过虚构人生实现。以下表达生成前必须检查 IP Fact Source：

我第一次… / 我以前… / 我喝了很多年… / 我每天… / 我家里常备… / 我夏天一直… / 我去过… / 我亲眼见过… / 我跟某某老师… / 我朋友… / 我客户… / 我妈… / 我老婆… / 我孩子… / 我上次送… / 有个粉丝跟我说…

**如果 IP 资料不存在：禁止生成。即使相关产品事实是真的。**

没有真实人物经历时，真人感来自**怎么判断**，不是**编发生过什么**。优先使用：

- 判断（我更看重……）
- 选择（这种茶我会先看……）
- 取舍（我宁可少一个卖点，也不会……）
- 边界（喜欢清香型的，这款未必适合你）
- 现场动作（你看，我把这一颗拆开）
- 用户问题（很多人第一次看到都会问……，前提确有普遍场景依据）
- 产品观察（泡开以后你可以自己看）

### 24.2 Professional Humility（专业谦逊）

专业 IP 必须有边界。禁止为了"像专家"写绝对判断：

- 一看就知道 / 这个骗不了 / 这样就是好 / 不这样就是差
- 别人学不来 / 机器一定不行 / 这个指标就能判断品质
- 一喝就知道 / 真正懂行的人都……

优先表达：

- 我自己通常会看……
- 这是我判断的其中一项。
- 单看这一项其实还不够。
- 不同工艺会有不同表现。
- 这个标准更适合我自己的筛选逻辑。

**越专业，越允许"不绝对"。** 高质量专业 IP 应该知道：什么可以判断、什么不能只靠一个指标判断、什么只是自己的偏好、什么存在不同做法、什么需要结合其他因素。禁止为了短视频传播把复杂专业知识强行压缩成错误二元结论。

### 24.3 与 Expression Authority 的配合

- 人格动作（第十三节）不等于人物经历：判断/选择/取舍/偏好/方法可以自由写，人生经历必须过 IP Fact Firewall。
- 专业表演感检测（第十六节）与 Professional Humility 互补：前者管"解释太多"，后者管"说得太绝对"。
- 生成后追加：事实扩张测试 + IP Fact Firewall 复查（见 `expression-authority.md` 第四节、第五节）。

## 最终目标

抖音 IP 卖货不是"一个人把产品参数说出来"，而是"一个有判断的人，顺手把自己为什么选这个东西讲明白"。

文案最终应该让用户感觉：**我不是在听广告，而是在听一个懂这个东西的人跟我讲他的判断。** 在此基础上再完成成交。

始终坚持：

```text
真人感 > 模板完整
人的判断 > 产品资料
一条讲透 > 卖点堆满
自然连贯 > 结构痕迹
长期信任 > 一次话术刺激
```
