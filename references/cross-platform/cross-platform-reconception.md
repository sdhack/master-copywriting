# Cross-Platform Re-conception Protocol（跨平台重新立题协议）

> **版本**：v1.1（v4.13.0 更新：新增三条跨平台爆款规律作为立题输入）
> **解决问题**：Platform Styling ≠ Platform Re-conception。同一套产品事实 + 换标题/篇幅/语气/平台结构 = 同一篇商业逻辑的四种包装。
> **第一原则**：跨平台不是改写，而是重新立题。
> **最高原则**：同一个人，不同平台，不是换一种说话方式，而是重新决定这一场为什么值得说。Platform Native 永远不能凌驾于 Identity Truth。四个平台可以有四种内容人格，但只能有一个真实的人。

---

## 〇、跨平台爆款规律输入（2026）

> 实证依据见 `viral-content-map.md`（Source of Truth：平台爆款内容与电商打法图谱）。**每个平台重新立题前，先过这三条跨平台规律**，再进入 Platform Content Brief。

### 0.1 情绪先行，信息后置

能引爆的内容先解决"情绪"，再解决"信息"。跨平台立题时，**每个平台的命题都必须先回答"用户此刻的情绪是什么"**，再回答"我要给什么信息"。

- 抖音：先让用户"想继续看"（好奇/共鸣/反差/共情），再给产品信息。
- 小红书：先让用户"觉得被说到"（痛点/向往/参考欲），再给决策信息。
- 视频号：先让用户"心里一动"（被理解/被认可/会心一笑），再给可信判断。
- 公众号：先让用户"觉得值得读"（认知缺口/情绪共振），再给论证。

**检查**：删掉情绪层后，产品信息是否还能被记住？如果情绪层只是装饰、删掉后信息照样成立 → 情绪层不合格，重新立题。

### 0.2 真实感是最强稀缺品（"活人感"取代精致人设）

2026 年滤镜拉满的精致内容全面跑输"粗糙但真实"的内容。跨平台立题时，**每个平台的命题都必须能承载"真实的人"**，而不是"完美的内容"。

- 允许不完美、允许留白、允许口语毛边、允许场景里的"乱"。
- 禁止过度打磨的"AI 精致感"（每句工整、信息齐全、结构闭环）。
- 立题时优先选"真实发生过 / 真实可拍 / 真实会说的话"，而不是"最工整的写法"。

**检查**：这篇内容是不是"太完美了"？如果每一句都工整、每个信息都完整、没有任何毛边 → 减掉过度完整，重新立题。

### 0.3 电商爆款 = 信任 × 场景，而非流量 × 低价

转化靠的是"信任的人 + 具体的使用场景"，不是流量堆砌或低价轰炸。跨平台立题时，**每个平台的卖货命题都必须同时回答"用户为什么信"和"用户能代入什么场景"**。

- 抖音：信任来自可拍可验证的现场证明；场景是用户能代入的使用瞬间。
- 小红书：信任来自可复查的决策信息；场景是用户正在经历的生活问题。
- 视频号：信任来自可信判断与边界；场景是值得转给熟人的现实情境。
- 公众号：信任来自逻辑与来源；场景是值得理解的需求与生活方式。

**检查**：这篇卖货命题里，用户为什么信？用户能代入什么场景？如果两个都答不上来 → 重新立题。

## 一、核心问题

系统已经能为四个平台生成不同形式的内容，但真实结果仍然是：

**Platform Styling ≠ Platform Re-conception**

即：同一套产品事实 + 换标题 + 换篇幅 + 换语气 + 换平台常见结构 = 同一篇商业逻辑的四种包装。

同时出现新的严重问题：

- 为了小红书原生感，AI 虚构普通消费者身份
- 为了视频号信任感，AI 虚构长期个人经历
- 为了公众号深度，把卖点扩写成长文章
- 为了抖音可看性，把过多产品信息塞进动作演示
- 四个平台重复大量相同卖点、价格、耐泡、售后
- 平台差异仍停留在语言表面

---

## 二、第一原则

> **跨平台不是改写，而是重新立题。**

同一个产品进入不同平台时，**禁止先写一篇母稿**，再分别：

- 缩短成抖音
- 加 emoji 变小红书
- 加长变公众号
- 放慢语气变视频号

必须从 Platform Core 重新开始。

---

## 三、Platform Content Brief（平台内容简报）

正式写四个平台之前，**分别内部生成一个 Platform Content Brief**。每个平台单独回答以下 6 个问题。

### 3.1 Platform Core（平台核心经营什么）

| 平台 | Platform Core |
|---|---|
| 抖音 | 注意力与观看推进 |
| 小红书 | 参考价值与决策价值 |
| 公众号 | 认知、观点与思想 |
| 视频号 | 信任与社交传播 |

### 3.2 Platform Question（平台最值得回答的问题）

同一个产品，在这个平台最值得回答的那个问题是什么？

**禁止四个平台回答同一个问题。**

### 3.3 User Gain（用户看完多得到什么）

| 平台 | User Gain |
|---|---|
| 抖音 | 一个值得继续看的发现 / 现场证明 |
| 小红书 | 一个以后购买可以使用的判断 |
| 公众号 | 一个新的理解框架 |
| 视频号 | 一个值得信任和转述的判断 |

### 3.4 Primary Proof（平台最适合的证据）

| 平台 | Primary Proof |
|---|---|
| 抖音 | 可见、可拍、可现场验证 |
| 小红书 | 可比较、可复查、可收藏 |
| 公众号 | 逻辑、背景、论证、来源 |
| 视频号 | 人物判断、现实经验、稳定信用 |

### 3.5 IP Asset（这一篇沉淀哪一种人物资产）

不得四个平台都只证明"我很懂产品"。

### 3.6 Product Role（产品在这一篇里是什么）

产品角色可以是：主角 / 证明案例 / 解决方案 / 选择结果 / 观点实例。

**不同平台可以不同。**

---

## 四、抖音专项规则

抖音不是：**产品说明书动态版。**

### 4.1 一个可拍的核心证明

每篇优先选择 **一个可以拍出来的核心证明**。

例如一篇围绕：拆开 → 泡开 → 某个变化。

就不要同时承担：

- 品类历史
- 工艺科普
- 价格教育
- 叶底教学
- 售后解释

### 4.2 Visual Claim Budget（视觉主张预算）

一篇抖音默认只围绕：

> 1 个核心观看问题 + 1 个核心产品证明 + 少量必要辅助事实。

不要把整个 Sell-point Skill 拍一遍。

### 4.3 语言的角色

如果一个镜头已经证明，语言负责解释 **"为什么值得继续看"**，而不是继续添加卖点。

---

## 五、小红书专项规则

### 5.1 最高规则：Platform Native Cannot Override Identity Truth

为了像小红书，**禁止自动创建**：

- 姐妹们都问我
- 我用了三年
- 我回购很多次
- 我买的这家
- 我闺蜜 / 我妈妈 / 我朋友
- 我亲测
- 我常喝

**除非真实身份资料明确支持。**

### 5.2 小红书原生感应该来自

- 搜索价值
- 决策细节
- 使用条件
- 比较逻辑
- 清楚的适合 / 不适合
- 真实身份下的经验

**不是来自**：姐妹 / 绝绝子 / 老茶客人设 / 假回购 / 假路人。

---

## 六、Commercial Identity Integrity（商业身份完整性）

写商业内容之前必须确认：当前内容主体与商品是什么关系？

可能包括：

- 品牌官方
- 店主 / 创始人
- 产品方
- 合作达人
- 佣金达人
- 赠品体验
- 真实消费者
- 无商业关系
- 未知

**平台风格不得改变这个事实。**

### 身份红线

- 如果当前主体是店主 → 不能为了 UGC 感写"我买的这家"
- 如果当前主体是品牌 → 不能假装"普通消费者偶然发现"
- 如果商业关系未知 → 不得自行伪装第三方消费者

---

## 七、公众号专项规则

公众号不是：**Long-form Sales Copy（加长版销售文案）。**

### 7.1 Central Thesis（中心论点）

进入公众号前必须产生 **Central Thesis**：这篇文章真正想让用户重新理解什么？

如果中心只能概括成"这个产品有三个优点" → 不合格。

### 7.2 产品出现可以更晚

优先结构：

```
问题 / 现象
    ↓
为什么值得讨论
    ↓
形成新的判断框架
    ↓
解释
    ↓
产品作为这个判断的实例 / 结果
    ↓
必要商业承接
```

而不是固定：产品卖点1 + 卖点2 + 卖点3 + 价格 + CTA。

### 7.3 Product Removal Test（产品移除测试）

暂时删除产品名。如果文章完全失去价值 → 说明它只是加长版商品详情。

好的公众号内容：即使暂时拿掉产品，核心观点仍然值得阅读。

产品回来以后，则证明：为什么这款产品符合这个观点。

---

## 八、视频号专项规则

视频号不是：**Slow Douyin（放慢的抖音）。**

不能只通过更慢语速 / 茶室 / 自然光 / 人生感悟 / 日常场景制造视频号感。

### 8.1 视频号真正的核心

> **这个判断为什么值得相信，并值得转给现实中的人。**

### 8.2 严格执行 IP Fact Firewall

禁止为了信任感自动写：

- 我每天都喝
- 我喝得最多
- 我做这个行业很多年
- 我见过很多
- 我年轻时候……
- 我一直坚持……
- 我的老客户……

**除非 IP Fact Source 明确提供。**

### 8.3 视频号的信任可以来自

- 判断有边界
- 选择有原则
- 不把话说满
- 对用户利益负责
- 解释简单
- 愿意承认"不适合"
- 产品与长期价值观一致

**不需要虚构人生履历。**

---

## 九、Cross-Platform Proposition Collision Check（跨平台命题碰撞检查）

四个平台生成完以后，只看核心命题。

如果四篇可以概括成同一句话："这款茶好、耐泡、手工、值得买。" → **失败，重新立题。**

### 四个平台的命题应该分别回答

| 平台 | 命题检验问题 |
|---|---|
| 抖音 | 这一篇究竟让我看到了什么？ |
| 小红书 | 这一篇究竟帮我做了什么决定？ |
| 公众号 | 这一篇究竟让我想明白了什么？ |
| 视频号 | 这一篇究竟让我更相信什么判断？ |

**四个答案必须明显不同。**

---

## 十、Cross-Platform Fact Selection（跨平台事实选择）

同一个 SKU 拥有一个统一 Product Fact Pool。

但是：**每个平台只选择当前命题真正需要的事实。**

不得因为"这些都是核心卖点"就四个平台重复：15泡 / 老丛 / 手作 / 非遗 / 价格 / 售后 / 香气。

> **事实统一，不代表每篇都要使用。**

### 10.1 Shared Fact Overuse Check（共享事实过度使用检查）

四平台批量生成后检查：如果某一个辅助卖点在四个平台全部出现 → 问：

> 它是否真的对四个平台的当前核心命题都不可替代？

如果不是 → 删除部分平台中的重复事实。

### 10.2 Platform-Specific Information Density（平台特定信息密度）

| 平台 | 信息密度原则 |
|---|---|
| 抖音 | 少而可看 |
| 小红书 | 足够决策 |
| 公众号 | 足够论证 |
| 视频号 | 足够信任 |

**禁止统一按照"产品信息越完整越好"。**

---

## 十一、Identity Consistency Across Platforms（跨平台身份一致性）

同一个 IP 跨四个平台，**人物现实身份必须一致**。

不能：

| 平台 | 身份（错误示例） |
|---|---|
| 抖音 | 卖茶老板 |
| 小红书 | 三年老茶客消费者 |
| 公众号 | 行业观察者 |
| 视频号 | 做茶几十年的老师傅 |

**除非这些身份本来都是真实成立。**

### 区分 Identity 和 Narrative Role

同一个真实身份（例如"茶馆经营者"）：

| 平台 | Narrative Role（叙述角色） |
|---|---|
| 抖音 | 现场演示者 |
| 小红书 | 购买建议提供者 |
| 公众号 | 行业 / 消费观察者 |
| 视频号 | 可信判断者 |

这是 **Narrative Role 变化**，不是 **Biography 变化**。

> 允许改变表达角色，不允许改变现实身份。

---

## 十二、External Intelligence 也必须按平台重新研究

同一产品四平台，**不得只做一次 Web Research 然后把 Top 5 问题分发四个平台**。

分别问：

- 抖音用户当前会因为什么停下来？
- 小红书用户搜索什么决策问题？
- 公众号什么外部信息值得形成认知？
- 视频号什么现实判断具有传播价值？

允许共享 External Facts，**不共享 Angle Ranking**。

---

## 十三、最终四平台 QA

生成完成后内部运行：

### Douyin Check

> 如果去掉画面动作，是不是只剩普通商品口播？
> 如果是 → 重新强化 Visual Proof。

### Xiaohongshu Check

> 有没有为了平台原生感伪造消费者身份、使用经历、回购经历？
> 有则删除。

### Official Account Check

> 去掉产品以后，文章核心观点还有没有阅读价值？
> 没有则重新立论。

### Channels Check

> 去掉"慢语速 / 茶室 / 人生感悟"，还剩不剩一个值得信任和转述的判断？
> 没有则重新立题。

## 十四、最终成功标准

同一个 SKU 生成四个平台时：

不应该像：**一个产品经理写了四种格式。**

而应该像：**同一个真实 IP 面对四种不同的内容环境，重新判断"在这里，什么最值得说"。**

最终保持：

- 事实相同
- 人物相同
- 价值观相同

但：

- 问题不同
- 内容价值不同
- 证明方式不同
- 产品角色不同
- 信息密度不同
- 用户心理变化不同

---

## 十五、最终最高原则

> **同一个人，不同平台，不是换一种说话方式，而是重新决定这一场为什么值得说。**
> **Platform Native 永远不能凌驾于 Identity Truth。**
> **四个平台可以有四种内容人格，但只能有一个真实的人。**
