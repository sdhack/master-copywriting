# 输出模板与 MD 文件生成（references/templates/output-templates.md）

> **Source of Truth：输出模板与 MD 文件生成契约。** 创作完内容之后，**强制套用本文件模板**，并**生成 `.md` 文件交付**。主 SKILL.md 与 final-output.md 只保留简要调用；本文件是模板结构与文件生成规则的唯一 Source of Truth。
> 适用范围：**所有平台、所有类型（普通/IP）、所有目的（内容/种草/卖货）、所有版本数（单版/多版/多平台）的最终交付。**
> 核心目标：**跨 agent、跨批次输出格式一致**，交付物可直接复制使用、可直接归档、可被下游流程（审核/投放）稳定解析。
> 最高原则：**内容先达标（Hard Gates 全过），格式再套模板（强制）。模板是交付外壳，不是内容替代品。**

---

## 一、强制应用规则（不可跳过）

1. **创作完内容之后，必须套用本文件模板**，不得自由排版输出。
2. **必须生成 `.md` 文件交付**（保存到工作目录），不得只在对话里输出正文。
3. 模板套用在 **G10 输出净化之后**执行：先净化内部元数据，再套模板，再落盘。
4. 对话内可同步展示正文，但**交付物以 `.md` 文件为准**。
5. 用户明确指定其他格式（JSON / 表格 / 其他宿主格式）时，遵从用户格式；除此之外一律套用本文件模板。

---

## 二、文件命名规范

```
{平台}-{产品}-{行动}-{YYMMDDHHMM}.md
```

- **平台**：抖音 / 小红书 / 公众号 / 视频号 / 多平台
- **产品**：产品名或品类简称（如 某款乌龙茶）
- **行动**：看播 / 预约 / 成交 / 留资 / 种草 / 加热 / 内容（对应本次第一目标口径）
- **YYMMDDHHMM**：生成时间戳（如 2608151530）

示例：
- `抖音-某款乌龙茶-看播-2608151530.md`
- `小红书-某款乌龙茶-种草-2608151530.md`
- `多平台-某款乌龙茶-成交-2608151530.md`

> 与 HTML 报告命名规范一致（`{平台}-{产品}-{行动}-{YYMMDDHHMM}.html`），仅扩展名不同。

## 三、模板结构

### 3.1 单版模板（1 版）

```markdown
# {平台} · {产品} · {目的} · {版本标题}

> 平台：{平台}｜类型：{普通/IP}｜目的：{内容/种草/卖货}｜人群：{目标人群}｜第一目标：{first_goal}

## 标题

{标题}

## 正文/口播

{完整正文或口播稿}

## 画面/节奏

- {画面建议 1}
- {画面建议 2}

## 时长

约 {N} 秒 / 分钟
```

### 3.2 多版模板（2 版及以上）

**每版独立多行表格**（版本标题行 + 角度行 + 完整口播稿行），版本间用空行分隔。每版口播稿必须能独立复制使用。

```markdown
# {平台} · {产品} · {目的} · {N} 版

> 平台：{平台}｜类型：{普通/IP}｜目的：{内容/种草/卖货}｜人群：{目标人群}

## 稿一 · {版本标题}

| 项目 | 内容 |
|---|---|
| 版本 | {版本标题} |
| 角度 | {角度} |
| 口播稿 | {完整口播稿，可多行} |

## 稿二 · {版本标题}

| 项目 | 内容 |
|---|---|
| 版本 | {版本标题} |
| 角度 | {角度} |
| 口播稿 | {完整口播稿，可多行} |

（后续版本依此类推，版本间用空行分隔）
```

### 3.3 多平台模板（跨平台）

```markdown
# {产品} · 多平台 · {目的} · {N} 平台

> 类型：{普通/IP}｜目的：{内容/种草/卖货}｜人群：{目标人群}

## 一、抖音

### 抖音 · {版本标题}

{按单版或表格模板填充}

## 二、小红书

### 小红书 · {版本标题}

{按单版或表格模板填充}

（后续平台依此类推）
```

## 四、模板填充规则

1. **版本标题**：一句话概括本版核心命题（如"经常出差的人，带什么茶方便"）。
2. **角度（多版表格行）**：本版角度，用于版本区分与审核（v4.11.3 例外：多版表格模板场景下角度随交付输出）。
3. **收口家族（Closing Family）**：任何场景都不输出（v4.11.3 硬规则）。
4. **内部元数据**（Product Role / IP Asset / Primary Proof / QA / Score / Route / Purpose 验证 / 字数 / Content Fingerprint）：默认不进入交付文件；用户明确要求创作分析时，在正文之后单独输出分析部分。
5. **口播稿**：必须完整、可独立复制使用，不得省略或留"同上"。
6. **画面/节奏**：仅短视频/口播类需要；长图文（公众号/小红书）可省略该行。

## 五、MD 文件生成执行步骤

1. 完成全部 Hard Gates（G1-G12）与 Humanization Pass。
2. 执行 G10 输出净化：剥离内部元数据。
3. 按本文件模板结构组织内容（单版/多版/多平台）。
4. 按命名规范生成文件名（`{平台}-{产品}-{行动}-{YYMMDDHHMM}.md`）。
5. 保存到当前工作目录。
6. 交付时给出文件链接，对话内可同步展示正文摘要。
