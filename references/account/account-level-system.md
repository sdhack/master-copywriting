# 多平台账号级内容决策系统 Account-Level System（v2.9 新增）

> **Source of Truth**：多平台账号级内容决策系统
> **定位**：从"单篇高质量文案生成"升级为"多平台账号级内容决策"。本轮升级不推翻已有能力，而是在现有系统之上新增顶层决策层，让每一篇内容不仅写得好，还知道为什么现在值得写、它在账号生命周期中承担什么角色、给 IP 积累什么资产。
> **核心目标**：单篇要好，一批不重复，长期必须积累，不同平台重新立题，同一个 IP 越写越清楚，不是越写越像模板。

---

## 0. 升级摘要

| 层次 | v2.8 | v2.9 |
|---|---|---|
| 单篇 | 确保高质量 | 保持高质量 |
| 一批（多版本） | 角度多样 / 证据多样 / IP 资产多样 | 增加内容角色组合分配 |
| 账号（长期） | 无顶层规划 | IP 资产分层积累 / 内容生命周期 / 历史去重 |
| 跨平台 | 独立生成 / 禁止一稿多改 | 必须重新立题（Re-conception） |

## 一、Audience Tension Discovery（用户矛盾发现）

### 1.1 核心逻辑

原来：`Product Truth → Angle Proposition`

现在升级：`Product Truth × Audience Tension → Angle Proposition`

### 1.2 常见用户矛盾类型

| 矛盾类型 | 示例 |
|---|---|
| 想要A，但担心B | 想要好茶，但是怕贵 / 想要方便，但是怕牺牲品质 |
| 想买好，但怕交智商税 | 别人都说好，我是不是交了智商税 |
| 想省钱，但怕便宜没好货 | 价格低了，是不是料不行 |
| 想专业，但嫌复杂 | 想学点知识，但是太复杂看不懂 |
| 想方便，但怕牺牲品质 | 方便包装，是不是偷工减料 |
| 想送得体，但怕送错 | 想送茶，但是不知道对方喝不喝这个 |
| 想快速决定，但信息太多 | 看了一堆推荐，不知道选哪个 |
| 已经有兴趣，但不知道选哪个 | 几款看起来都差不多，怎么选 |
| 想尝试，但怕买回来不会用 | 想买，但买回来放着不会泡浪费了 |

### 1.3 生成规则

候选角度优先从**"用户正在纠结什么"**产生，而不是从**"产品还有什么卖点没写"**产生。

每个候选角度内部必须回答：**用户为什么会在意这件事？** 如果回答不了 → 降低优先级。

**增加权重因素**：用户真实存在的矛盾 > 产品卖点延伸。

## 二、Claim–Proof Matching（主张证据匹配）

### 2.1 核心原则

不再只要求"有证据"，而是要求**什么主张匹配什么证据**。禁止用与主张关系弱的"万能证据"证明所有卖点。

### 2.2 匹配表

| 主张类型 | 优先证据类型 | 禁止万能证据 |
|---|---|---|
| **便利性** | 实际操作 / 时间 / 步骤 / 使用场景 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |
| **价格价值** | 价格 / 规格 / 单次使用 / 成本逻辑 / 同维度比较 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |
| **工艺价值** | 生产事实 / 工艺过程 / 人物或生产信息 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |
| **体验** | 可观察表现 / 真实体验描述 / 实际演示 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |
| **品质** | 多维证据，而不是单一指标 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |
| **适配性** | 用户需求条件 / 使用条件 / 口味偏好 | 非遗 / 老师傅 / 用户自己试 / 耐泡 |

### 2.3 检查规则

每篇写完主张后问：**这个主张用的证据，是不是最匹配的？** 如果不是，换。

## 三、Platform-Specific Proof Preference（平台偏好证据）

不同平台的证据呈现方式偏好不同，同一个事实必须按平台偏好选择证据类型。

### 3.1 抖音

**优先：看得见的证据**

- 动作
- 对比
- 演示
- 前后变化
- 实物

### 3.2 小红书

**优先：可以保存和复查的证据**

- 参数
- 对比
- 使用细节
- 适合/不适合
- 选择标准
- 清单

### 3.3 公众号

**优先：逻辑证据**

- 原因链
- 背景
- 案例
- 数据
- 推理
- 方法体系

### 3.4 视频号

**优先：可信、容易理解和转述的证据**

- 人物判断
- 实际经验
- 现场说明
- 现实场景
- 简单事实

## 四、Account-Level IP Asset Planning（IP 资产规划）

### 4.1 核心问题

原来：每篇保证"每篇有 IP"。

现在升级：**一个账号长期在积累哪些人物资产？** 建立 IP Asset Map。

### 4.2 IP 资产候选清单

- 专业能力
- 选品能力
- 做事原则
- 价格观
- 用户立场
- 审美
- 行业判断
- 诚实边界
- 服务意识
- 长期主义
- 性格
- 方法论

### 4.3 生成前检查规则

生成单篇内容前，如果上下文包含最近一批内容，读取其 IP 资产指纹：

- 检查最近一批内容已经反复强化什么资产
- 如果某个资产出现过多 → 优先考虑其他符合人设的资产
- 目标：人格长期一致，但越来越立体

**禁止**：每一篇都只在证明"我很专业"。

---

## 五、IP Asset Hierarchy（IP 资产分层）

### 5.1 三层结构

| 层级 | 定义 | 强化频率 |
|---|---|---|
| **Core Assets** | 账号必须长期重复强化的底层人格。<br>例如：诚信、选品严格、专业。 | 每次内容都可以体现（通过判断方式） |
| **Supporting Assets** | 支撑形象、让人格立体的具体特质。<br>例如：价格观、审美、生活方式、服务态度。 | 间歇轮换，同一批不重复 |
| **Contextual Assets** | 特定内容才出现的特质。<br>例如：幽默、情绪、家庭角色。 | 只在适合的内容出现 |

### 5.2 Creative Variation 规则

Creative Variation 生成多版本时：

- 保持 Core Assets 稳定
- 适度轮换 Supporting Assets
- 做到：人格稳定，但内容不单调

## 六、Content Portfolio Role（内容组合角色）

### 6.1 核心原则

多版本生成时，不仅检查角度不同，还要给不同内容分配不同的**Content Role**（内容在组合中承担什么功能）。

### 6.2 角色候选

| 角色 | 功能 |
|---|---|
| **Attention Builder** | 吸引注意力，引入主题 |
| **Problem Clarifier** | 帮用户把问题说清楚，建立认知 |
| **Knowledge Builder** | 建立选择标准、传递方法 |
| **Trust Builder** | 建立 IP 信任和专业形象 |
| **Product Understanding** | 帮助理解产品特质 |
| **Desire Builder** | 建立用户欲望 |
| **Objection Resolver** | 解决常见异议 |
| **Comparison Helper** | 帮助对比选择 |
| **Decision Closer** | 推动最终决策 |
| **Relationship Builder** | 强化 IP 关系，不直接卖货 |

### 6.3 组合示例

用户要求 5 版 IP 卖货，不要求 5 篇全部是 Decision Closer。可以组合：

1. Trust Builder → 建立信任
2. Objection Resolver → 解决价格异议
3. Product Understanding → 讲产品差异
4. Comparison Helper → 现场证明
5. Decision Closer → 推动决策

### 6.4 不变原则

内容角色可以不同，但**总模式不变**（IP 卖货总体目标还是卖货）。每个角色最终仍需和当前 SKU 建立关系：

- Trust Builder 不能变成纯人物故事
- Knowledge Builder 不能变成纯知识科普，知识最后必须帮助产品决策
- Relationship Builder 不要求直接成交，但也不能和产品完全无关

即：**内容角色不同，但总模式不变（Portfolio Diversity ≠ Mode Drift）**。

---

## 七、Portfolio Diversity ≠ Mode Drift（组合多样不模式漂移）

**规则**：内容角色可以不同，但不能因为组合化导致模式漂移。

- IP 卖货中的 Trust Builder，最终仍需和当前 SKU 建立关系，不能变成纯人物故事
- IP 卖货中的 Knowledge Builder，知识最后必须帮助产品决策
- 即：**内容角色不同，但总模式不变**

---

## 八、Cross-Platform Re-Conception（跨平台重新立题）

### 8.1 最高规则

**跨平台不是 Rewrite（改写），而是 Re-conception（重新立题）**。

同一个产品事实进入不同平台时，必须重新判断：**这个平台的用户为什么会关心这个事实？**

禁止：
```
抖音短一点
↓
小红书加emoji
↓
公众号加长
↓
视频号语气放慢
```

### 8.2 同一事实的四平台转换示例

事实：**从几百款产品中筛选出当前 SKU**

| 平台 | 内容价值重新定义 |
|---|---|
| **抖音** | 现场筛选过程 / 冲突好奇 / 结果呈现 |
| **小红书** | 我的选择标准是什么 / 对比了哪些 / 决策方法 |
| **公众号** | 选择过载怎么办 / 我的判断体系是什么 |
| **视频号** | 我的做事原则 / 为什么宁缺毋滥 |

### 8.3 核心

不是改变长度和措辞，而是**平台重新定义这个事实的内容价值**。

## 九、Content Fingerprint（内容指纹）

### 9.1 结构

每篇内容生成一个不向用户展示的内部指纹，用于同批去重、历史去重、系列规划。

```text
Core Proposition
Audience Tension
Primary Fact
IP Asset
Proof Type
Narrative Driver
Content Role
Decision Path
Tone
```

### 9.2 用途

- 同批语义距离计算（辅助 Dynamic Angle Discovery）
- 历史批次去重（Recent Content Memory）
- IP 资产使用统计（避免单一资产过度使用）
- 内容生命周期跟踪
- 账号级内容规划

指纹不输出给用户，仅内部决策使用。

## 十、Recent Content Memory（近期内容记忆）

### 10.1 规则

如果当前上下文包含历史文案（最近一批/最近发布），读取这些内容的指纹。

下一篇优先避免：

- 同一个问题
- 同一个核心卖点
- 同一个证据类型
- 同一个 IP 资产
- 同一个开场驱动
- 同一个决策路径

### 10.2 Strategic Reinforcement 例外

重要的 IP 核心价值观可以重复，但必须满足至少一项变化：

- 新问题
- 新证据
- 新用户阶段
- 新场景
- 新产品
- 新结论层级

否则：避开，换角度。

## 十一、Repetition vs Reinforcement（重复还是强化）

必须区分：

| 类型 | 判断 | 处理 |
|---|---|---|
| **Repetition** | 同一个观点 + 同一个证据 + 同一种写法 | 应避免 |
| **Reinforcement** | 同一个核心价值观，通过不同真实问题反复体现 | 应保留（这就是人设） |

示例：IP 长期坚持"不把话说满"。不同内容可以通过价格/产品适配/功效边界/选品/对比反复证明 — 这叫人设，不是模板。

---

## 十二、Series Thinking（系列思维）

### 12.1 规则

如果一个优质角度不能在一篇讲完 → **允许主动拆成系列**。

示例："新手怎么选茶"可以拆：

A. 第一步看什么？
B. 哪些指标不用迷信？
C. 价格怎么看？
D. 第一次怎么买？

### 12.2 使用条件

- 用户只要求单篇 → 不要强行输出系列
- 用途：内容规划 / 多版本生成 / 连续内容生产

---

## 十三、Information Lifecycle（内容资产生命周期）

### 13.1 四个阶段

| 阶段 | 定义 | 角度选择优先级 |
|---|---|---|
| **New** | 从未讲过 | 优先考虑（如果匹配当前需求） |
| **Developing** | 讲过一次，可以继续深化 | 可选择 |
| **Established** | 已经成为 IP 长期观点 | 低优先级 |
| **Overused** | 最近使用过多 | 暂时降低优先级 |

### 13.2 Dynamic Angle Discovery 结合

Dynamic Angle Discovery 评分时，将生命周期状态纳入评分：

- New → 加分
- Overused → 减分

避免：一个卖点因为表现好，连续 20 篇反复使用。

## 十四、Platform Content Portfolio（平台内容组合原则）

多条内容组合时，不同平台组合重点不同。

### 14.1 抖音

Portfolio 优先保持：

- 注意力入口多样
- 演示方式多样
- 用户问题多样
- 内容节奏多样

### 14.2 小红书

Portfolio 优先保持：

- 搜索词覆盖
- 决策问题覆盖
- 使用场景覆盖
- 对比维度覆盖

### 14.3 公众号

Portfolio 优先保持：

- 观点体系逐渐深化
- 长期主题连续
- 方法体系可积累

### 14.4 视频号

Portfolio 优先保持：

- 信任资产
- 人物稳定性
- 可转述观点
- 现实关系场景

## 十五、三层 QA（质量不只检查单篇）

### 15.1 Piece-Level QA（单篇级）

这一篇好不好？检查项与 v2.8 相同。

### 15.2 Batch-Level QA（批次级）

这一批（多版本）是不是好？检查：

- 角度是否真的不同
- 证据机制是否多样
- IP 资产是否多样
- 收尾方式是否多样
- Content Role 组合是否合理
- 模式是否都不漂移

### 15.3 Account-Level QA（账号级）

最近一段时间是否：

- 某卖点过度使用
- 某 IP 资产过度使用
- 某种结构过度使用
- 内容角色失衡
- 平台价值越来越单一

发现任一问题 → 下一批选题主动调整。

---

## 十六、多平台不能共享同一内容组合

如果用户要求同一产品四个平台各 5 篇：

- 不能先做一个 20 篇选题池，然后平均分配
- 必须分别执行：`Platform → Audience Tension → Angle Discovery → Portfolio Selection`
- 最终四个平台应该拥有明显不同的：用户问题 / 内容命题 / 证据 / 内容角色 / 决策路径
- 允许共享产品事实，不应共享完整内容逻辑

---

## 十七、规则隐形原则

新增的 `Audience Tension / Claim-Proof Matching / IP Asset Map / Content Role / Fingerprint` 全部属于**内部决策变量**。

**最终成品禁止出现：**

```
用户矛盾：
证据：
IP资产：
内容角色：
```

规则必须继续隐形，不允许在成品中露出决策过程痕迹。

---

## 十八、保持已有效原则

继续保持以下所有原则，不修改：

- 动态选题（Dynamic Angle Discovery）
- 自然充分（Natural Depth）
- 一个角度一个核心命题
- 不越权扩展事实（Expression Authority）
- 不编 IP 经历（IP Fact Firewall）
- 多版本语义距离（Semantic Distance Selection）
- 真人表达（Humanization Pass）
- 规则隐形（Anti-Patternization）
- Mode Completion Gate（模式完成优先）

不要因为账号级优化重新变得复杂、机械。

---

## 十九、最终目标

Master Copywriting 不再只回答：

> "这一篇怎么写？"

还要回答：

> "这一篇为什么现在值得写？"
> "它和之前内容有什么不同？"
> "它在这个平台承担什么作用？"
> "它给 IP 账户新增什么资产？"
> "用户看完以后，离最终目标前进了哪一步？"

最终把 Skill 从：

# 单篇文案生成系统

升级成：

# 多平台内容决策与 IP 资产积累系统

**最高原则**：
- 单篇要好
- 一批不能重复
- 长期必须积累
- 不同平台必须重新立题
- 同一个 IP 越写越清楚，而不是越写越像模板
