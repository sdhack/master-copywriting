# 动态角度发现引擎 Dynamic Angle Discovery Engine（references/dynamic-angle-discovery.md）

> **Source of Truth：动态角度发现引擎。** 主 SKILL.md 只保留简要调用；本文件是 Dynamic Angle Discovery 的唯一 Source of Truth。
> 适用范围：**所有平台、所有类型（普通/IP）、所有目的（内容/种草/卖货）的多版本生成。**
> 解决：多版本角度固定化——用户要求"生成5版"时，AI 反复生成"形态好奇版/香气记忆版/冷泡场景版/避坑教学版/送礼场景版"固定五件套，Creative Variation 退化成"固定五槽位模板"。
> 核心原则：**先发现有哪些真正值得写的角度，再从中选5个。** 用户要求"生成5版"只代表"找5个当前值得写、彼此有明显差异的创意方案"，不是"填满5个固定内容槽"。
> 本轮禁止：新增公式 / 新增钩子 / 新增心理模型 / 扩大 24 模式 / 修改四平台 Canonical Core / 增加大量新变量 / 继续简单增加"真人感规则"。本层只解决"讲什么"。
> v2.8 新增：Angle 必须绑定 IP Asset（七·一节）、Angle-Specific Mode Completion（八·一节）。

---

## 一、取消固定"5版 = 5种角度"

Skill 中不得存在任何固定映射：

```text
第1版 = 好奇
第2版 = 香气
第3版 = 场景
第4版 = 避坑
第5版 = 送礼
```

同样禁止：

```text
第1版 = 痛点
第2版 = 对比
第3版 = 教程
第4版 = 故事
第5版 = CTA
```

**"生成5版"只代表：找5个当前值得写、彼此有明显差异的创意方案。** 不是填满5个固定内容槽。任何"第N版 = 某类角度"的固定映射在本 Skill 中一律禁止。

---

## 二、写正文之前必须先执行 Angle Discovery

收到多版本内容生成任务以后，**禁止立刻开始"稿1……"**。内部必须先产生 **12—20 个候选 Angle Propositions**。

- 任务简单（单条、非商业、信息极少）可以减少，但**默认多版本商业任务应有足够大的候选池**（12-20 个）。
- 候选角度必须从**当前真实信息**中产生，不得直接从固定的"爆款角度列表"取5个。
- Angle Discovery 是**写正文前的强制步骤**，不是可选项。

---

## 三、候选必须是 Angle Proposition，不是标签

禁止只生成"香气版/工艺版/场景版/送礼版/避坑版"——这些只是分类标签。真正候选必须是一条**可以展开、可以证明、可以服务用户心理变化的具体命题**。

| 禁止（标签） | 推荐（命题） |
|---|---|
| 方块版 | 为什么某款乌龙茶压成一颗方块，对嫌每次称茶麻烦的人反而更方便？ |
| 香气版 | 为什么这个 IP 判断乌龙茶，不先看香有多冲，而看香能不能进入茶汤？ |
| 价格版 | 198 拍一发二，用户真正应该比较的是单盒价格，还是这批茶本身的料、工艺和耐泡表现？ |
| 送礼版 | 为什么送一个长期喝熟普的人某款乌龙茶，可能并不是最稳的选择？ |

**候选角度必须回答：这一篇到底准备讲清楚什么？** 如果一条候选只能用两三个词描述（"香气""送礼"），说明它还不是命题，需要继续深化。

## 四、Angle Discovery 至少从多个维度寻找

以下维度用于**拓宽搜索空间**，不是"每次必须选一篇"的固定栏目。从多个维度生成候选，避免只从一个维度（如"产品形态"）反复挖。

| 维度 | 探索问题 |
|---|---|
| Product Truth | 产品本身有什么值得讲？ |
| User Problem | 用户现在有什么具体问题？ |
| Decision Question | 用户买之前真正纠结什么？ |
| IP Judgment | 这个 IP 对这类产品有什么选择标准？ |
| Usage Moment | 什么时刻这个产品价值最明显？ |
| Misunderstanding | 用户对这个品类有哪些常见误解？ |
| Demonstration | 有哪些内容可以现场证明？ |
| Comparison | 用户实际上会把它跟什么选择比较？ |
| Objection | 不买它的合理理由是什么？ |
| Hidden Detail | 消费者容易忽略什么细节？ |
| Price / Value | 价格为什么值或不值？ |
| Social Context | 送人、办公、家庭、招待等场景是否真实成立？ |
| Proof | 什么事实最适合用来支撑决策？ |
| Product-IP Relationship | 为什么这个产品最终进入这个 IP 的选择？ |

**注意：这些是探索维度，不是"每次必须选一篇"的栏目。** 目的是让候选覆盖不同信息空间，而不是再建一套固定栏目。

## 五、平台必须参与 Angle Discovery

不能先选5个角度、再做平台适配。**平台从选题阶段就要介入。**

### 5.1 抖音

优先选择：有视觉动作 / 有现场变化 / 容易快速理解 / 能制造继续观看理由 / 用户问题明确 / 能现场验证 / 有人物判断 的角度。

抖音角度不只是"知识有没有价值"，还要考虑：**能不能拍出来？** 一个再好的命题如果镜头无法承载，就不适合抖音。

### 5.2 小红书

优先：搜索问题 / 购买比较 / 选择标准 / 使用细节 / 适合-不适合 / 实际决策 / 避坑 / 可收藏 的角度。

核心判断：**用户以后做决定时会不会回来找这篇？** 有搜索与收藏价值的角度优先。

### 5.3 微信公众号

优先：认知问题 / 消费判断 / 品类背后逻辑 / 产品选择哲学 / IP 长期观点 / 用户为什么会形成错误判断 / 生活方式与价值选择 的角度。

核心判断：**这件事有什么值得被真正想明白？** 观点必须能被论证，不能只有信息罗列。

### 5.4 视频号

优先：信任判断 / 现实生活问题 / 熟人关系 / 有阅历的选择逻辑 / 家庭-朋友可转述问题 / 产品是否靠谱 / 长期信用 的角度。

核心判断：**这是不是一句值得现实中转给别人听的话？** 可信、可转述优先。

## 六、24 模式必须参与 Angle 评分

不能只找"好内容"，必须找**最符合当前模式的好内容**。

| 模式 | 角度筛选重心 |
|---|---|
| 抖音 × IP × 卖货 | 候选角度最终必须有潜力帮助用户理解"为什么这个人选择当前 SKU，我为什么值得买"。单纯"方块很新奇"可能适合内容/种草，但未必是最强卖货角度。 |
| 小红书 × 普通 × 种草 | 哪个角度最容易让用户把产品加入候选清单？ |
| 公众号 × IP × 内容 | 不需要强行围绕产品卖点，更应该寻找"什么问题最能强化这个 IP 的思想资产"。 |
| 视频号 × IP × 卖货 | 什么判断既能卖货，又最保护长期信用？ |

## 七、候选角度评分机制（Angle Scoring）

内部对候选角度逐项打分（0-2 三级，与行为锚点评分一致）。**评分不向用户展示。**

| 维度 | 判断问题 |
|---|---|
| Mode Fit | 符合当前内容/种草/卖货模式吗？ |
| Platform Fit | 适合当前平台吗？ |
| Fact Strength | 有足够真实素材支撑吗？ |
| User Relevance | 目标用户为什么会关心？ |
| IP Value | IP 模式下能沉淀人物判断吗？ |
| Conversion Value | 卖货模式下能减少购买阻力吗？ |
| Content Potential | 能形成具体内容、画面、细节吗？ |
| Novelty | 与其他候选是否足够不同？ |
| **Saturation（v3.1）** | 这个角度是不是全网已经写烂？写烂 → 减分（Saturation Penalty） |
| **Information Gain（v3.1）** | 用户看完比看普通同类内容多知道了什么？只是复述常识 → 减分 |

**规则**：Novelty（新）不能高于 Fact Strength 和 Content Potential（能不能写充分）。一个角度再新奇，如果事实太弱、内容撑不满一篇，应降低评分或淘汰。

### 7.1 Saturation Penalty（饱和惩罚，v3.1 新增）

如果研究发现全网大量内容都在讲**产品形态 / 基础香气 / 基础泡法**，这些角度**不是禁止使用，但 Angle Score 降低**。

只有当前 IP 能够提供以下任一项时才重新考虑：

- 新判断
- 新证据
- 新用户问题
- 新演示
- 新决策价值

**原则：热门 ≠ 值得重复。** 一个角度"用户感不感兴趣"不等于"值得现在写"；还要看当前 IP 能否提供普通同类内容没有的东西。

### 7.2 Information Gain Score（信息增量评分，v3.1 新增）

最终 Angle 不仅判断"用户感不感兴趣"，还要判断：

> 用户看完以后，比看普通同类内容多知道了什么？

Information Gain 可以来自：

- 新问题
- 新判断
- 新选择标准
- 新证据
- 新解释
- 新决策方法
- IP 特有观点

**如果一篇只是把网上普遍都知道的信息重新说一遍，降低优先级。**

### 7.3 Category Diversity（内容功能多样性，v3.1 新增）

Dynamic Angle 已经避免固定五槽位，但还要避免：**5 篇虽然 Angle 不同，实际全部属于教学类。**

内部增加 **Content Function** 分类：

> 解释 / 决策 / 异议 / 演示 / 观点 / 比较 / 价值 / 使用 / 信任 / 认知

用户要求 5 版时，不要求五类各一篇，但**如果 4 篇以上都属于同一种 Content Function，重新检查组合是否过窄**。例如 5 版全是"解释/科普"结构，即使角度不同，用户感知仍是同一类内容。

## 七·一、Angle 必须绑定 IP Asset（IP 资产绑定）

多版本 IP 内容生成前，为每个入选角度内部选择**最适合沉淀的一项人物资产**。

IP 资产候选：选品能力 / 专业判断 / 价格观 / 做事原则 / 用户立场 / 审美偏好 / 对行业的理解 / 克制 / 诚实边界 / 服务意识 / 对复杂问题的处理方式。

| 角度 | 适合沉淀的 IP 资产示例 |
|---|---|
| 选品过程 | 选品能力 / 做事原则 |
| 价格异议 | 价格观 / 对行业的理解 |
| 冲泡节奏 | 专业判断 / 对用户的态度 |
| 工艺选择 | 审美偏好 / 做事原则 |
| 口感偏好 | 审美偏好 / 克制 |

**规则：**
- 5 版 IP 内容至少体现 **2-3 种不同人物资产**。
- 同一批内，**3 篇以上不得沉淀同一种人物资产**。
- 不要为了多样性强行造人格，必须符合已有 IP 定位。
- **人格一致，不等于每篇只重复同一人格资产。**

**检查：每篇删除产品名后，能感受到的"这个人怎么做选择"是否与分配的人物资产一致？** 不一致 → 该角度的 IP 资产分配失败，重新分配。

## 八、Semantic Distance Selection（语义距离选择）

最终选择5个角度时，**不能只选单篇最高分**，还必须保证**五个角度之间有足够语义距离**。

### 8.1 同母题去重

以下候选可能都是"香气"这个母题：

- 兰花香
- 奶香
- 挂杯香
- 香落水
- 十五泡香还在

**不能全部占5版。** 默认只选择其中最强的一个（按当前平台 × 当前模式的价值判断）。

以下候选可能都属于"送礼决策"：

- 送朋友
- 送长辈
- 送客户

**默认只能选择其中最强的一种**，除非用户明确要求围绕送礼展开。

### 8.2 一个核心事实不能无限拆成多版

例如"紧压方块"可以产生：形态好奇 / 一颗一泡 / 出差方便 / 包装记忆。但**默认不应同时占4版**。应该选择当前平台 × 当前模式下价值最高的那个命题，其他版本优先探索其他事实和用户问题。

### 8.3 允许"同一核心价值的不同决策问题"，但必须真正不同

例如产品一个很强的优势是"紧压一颗一泡"，可以有：

- A：为什么对新手更省事？
- B：为什么出差携带更方便？

但只有在**用户问题不同、决策理由不同、内容推进明显不同**时才允许同时存在。如果只是"同一个卖点换一个场景"，优先保留更强的一版。

## 八·一、Angle-Specific Mode Completion（角度独立完成模式）

Dynamic Angle Discovery 选出不同角度以后，**不允许用统一 CTA / 自己试试 / 链接在下面 把所有角度强行变成卖货。**

每个角度必须重新回答：**这个角度本身，怎样自然完成当前模式？**

| 任务：抖音 × IP × 卖货 | 角度自然完成卖货的方式 |
|---|---|
| 选品过程角度 | 通过"为什么最后留下当前 SKU"完成购买理由 |
| 价格异议角度 | 通过"为什么这个价格值得"完成购买决定 |
| 冲泡角度 | 通过"正确冲泡如何体现当前 SKU 价值"连接商品 |
| 工艺角度 | 通过"IP 为什么选择这种工艺路线"完成选择 |

**规则：不要求每篇使用同一个成交结构。** 成交必须由角度自然产生，而不是在角度讲完后统一追加"想试的拆一颗泡"。

**检查：删除统一 CTA 后，每篇是否仍然通过自己的角度逻辑完成了模式目标？** 如果删掉统一 CTA 后卖货模式消失，说明该角度没有独立完成模式，需要重新设计该角度的成交路径。

与 Natural Depth 的关系：Angle-Specific Mode Completion 决定"每个角度用什么路径完成模式"；Natural Depth 决定"这条路径讲多深才够"（见 `natural-depth.md`）。

## 九、Previous Batch Exclusion（历史批次去重）

如果上下文里已经存在前一批文案，提取上一批的：核心命题 / 核心卖点 / 用户问题 / Narrative Driver / 主要证据。

用户再次要求"再来5版"时，**默认优先避开已经充分覆盖的内容空间**。除非：

- 用户明确要求沿用
- 当前核心卖点非常重要
- 能形成真正不同的新命题

**禁止**：

```text
上一批：形态 / 香气 / 冷泡 / 避坑 / 送礼
下一批又：形态 / 香气 / 冷泡 / 避坑 / 送礼
只改标题和句子。
```

## 十、Example Anti-Anchoring（示例不得成为选题锚点）

全面检查 SKILL.md、examples.md、platforms.md、24-modes.md、references 中所有示例：

- 如果某处长期使用"形态好奇 / 香气记忆 / 冷泡场景 / 避坑教学 / 送礼"作为五版示例，**必须削弱锚定**。
- 任何示例中的角度、顺序、标题、产品、Narrative Driver，**都仅用于解释机制，不得作为下一次生成的默认候选**。

**原则：示例是"机制演示"，不是"选题清单"。** 示例里出现的角度不得成为默认候选池。

## 十一、Angle Quality 不仅看"新"，还要看"能不能写充分"

动态发现角度后，不能因为角度新奇就选。还要判断：**这个角度有没有足够真实内容支撑成一篇完整成品？**

例如候选"棉纸为什么更有文化感？"如果产品资料只能提供"棉纸包装"，没有足够内容，**不应为了创新硬写300字**。降低评分或淘汰。

**原则：差异性不能牺牲有效性。** 用户要求5版，如果有20个候选，选择5个最值得写的；不能为了"五篇必须完全不同"而选择与用户无关、事实太弱、与模式不符、没有足够内容深度的角度。

---

## 十二、Dynamic Angle 与 Narrative Driver 分开

先决定 **What to say**（角度/命题），再决定 **How to move**（Narrative Driver）。

Narrative Driver 可包括：问题驱动 / 动作驱动 / 判断驱动 / 用户决策驱动 / 现场验证驱动 / 对比驱动 / 误区驱动 / 使用场景驱动。

**禁止用不同 Narrative Driver 冒充不同 Angle。** 两个候选如果核心命题相同、只是推进方式不同，它们是一个角度，不是两个。

---

## 十三、最终最高原则

> **先找对值得讲的事情，再把这件事情自然讲够。**
> 而不是：**先决定写五篇，再想办法填满五个模板。**

一句话概括本层目标：

> **把"固定五版、越写越薄"的生成器，升级成"动态发现选题 + 自然充分表达"的内容决策引擎。**

## 与相邻 reference 的边界

- `natural-depth.md` 管**讲到什么程度**（Depth Budget / Conversational Flow Check / Mode Completion Gate / Narrative Detail Boundary）；本文件管**讲什么**（Angle Discovery / Angle Scoring / Semantic Distance / IP Asset 绑定 / Angle-Specific Mode Completion）。两者必须串联：先发现角度并绑定 IP Asset，再判断深度，再为每个角度设计独立成交路径。
- `anti-patternization.md` 管**规则不可见**（Narrative Driver / Structural Diversity / Set-Level QA）；本文件补充"角度本身要动态发现"，Set-Level QA 的固定选题检查与过度稀释检查引用本文件。
- `platforms.md` 定义平台规律与中心思想（Canonical Core）；本文件只要求"平台从选题阶段介入"，**不修改平台中心思想**。
- `examples.md` 提供结构演示；本文件要求示例不得成为选题锚点（Example Anti-Anchoring）。
- `24-modes.md` 定义 24 模式中心思想；本文件要求 24 模式参与 Angle 评分，**不扩大 24 模式**。
