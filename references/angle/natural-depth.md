# 自然充分度层 Natural Depth Layer（references/natural-depth.md）

> **Source of Truth：自然充分度层。** 主 SKILL.md 只保留简要调用；本文件是 Natural Depth Layer 的唯一 Source of Truth。
> 适用范围：**所有平台、所有类型（普通/IP）、所有目的（内容/种草/卖货）的文案生成。**
> 解决：自然充分度不足——AI 为了去 AI 感、去模板、留白、自然结束，把内容压得过短、过薄，导致短句像提词器、前后缺少自然推进、IP 资产变弱、卖货模式漂移成内容/种草、SKU 选择理由不充分、CTA 删掉以后连成交逻辑也消失、为了"不完整"而提前结束、用户要求 300 字左右结果只剩简单信息摘要。
> 核心原则：**自然不等于短；每个入选角度必须讲到足以完成当前心理目标的程度；不过度展开，也不过度压缩。**
> 本轮禁止：新增公式 / 新增钩子 / 新增心理模型 / 扩大 24 模式 / 修改四平台 Canonical Core / 增加大量新变量 / 继续简单增加"真人感规则"。本层只解决"讲到什么程度"。
> v2.8 新增：Narrative Detail Boundary（七·一节）、Sentence-End Amplification Check 引用（第十二节）。

---

## 一、动态选中角度以后，必须判断"讲多深才够"

Angle Discovery 解决**讲什么**，Natural Depth 解决**讲到什么程度**。两者必须串联。

**不得出现：选出了一个很好的角度，最后却只写成 100 多字的产品摘要。**

判断标准不是"内容看起来够自然了吗"，而是：**用户是否已经发生当前模式要求的心理变化？**

---

## 二、自然不等于短（Short Sentence ≠ Human Speech）

禁止为了真人感把内容机械切成"产品事实一句 / 参数一句 / 工艺一句 / 体验一句 / CTA一句"这种**短句提词器**。

真人表达必须存在**连续话流**：前一句应该自然产生下一句。可通过以下方式建立连接：

- 因果
- 追问
- 动作
- 用户反应
- 判断
- 解释
- 比较
- 现场观察
- 场景推进

**原则：短句是结果，不是方法。** 真人说话有时长句、有时短句，节奏来自内容需要，不是来自"每句都要短"。

---

## 三、Conversational Flow Check（对话流检查）

每 3—5 句检查一次：**下一句为什么会接在上一句后面？**

如果只能回答"因为还有另一个卖点没说"，则失败。

失败示例（仅靠信息罗列连接）：

```text
香气
↓
第四代传承人
↓
价格
↓
CTA
```

如果这些信息之间没有自然逻辑关系，**不能因为信息都是真实的就直接拼在一起**。必须重建因果/追问/动作/反应/判断/解释/比较/现场观察/场景推进的连接。

---

## 四、留白不等于任务没做完

允许：

- 少讲卖点
- 不总结
- 不升华
- 没有独立金句
- 没有显式 CTA

但：

**当前第一目标必须完成。** 留白是"删掉不必要的"，不是"把必要的也删掉"。

---

## 五、Mode Completion 优先于 Anti-Patternization

尤其 **IP × 卖货**：即使没有显式 CTA，最终必须自然回答：

1. 为什么这个 IP 选当前 SKU？
2. 为什么这款 SKU 可能适合当前目标用户？
3. 用户现在为什么已经拥有足够信息完成购买决定？

**漂移判定**：

| 用户看完的感受 | 判定 |
|---|---|
| 只学到知识，没有形成"为什么买这个 SKU" | 卖货 → 漂移成内容 |
| 只是"好像挺想试"，但没有决策信息 | 卖货 → 漂移成种草 |
| 种草内容变成强逼单 | 种草 → 漂移成卖货 |
| IP 内容丢失人格特征 | IP → 漂移成普通 |

**卖货不能因为追求自然而被删没。** Anti-Patternization 只消除"规则痕迹"，不消除"模式目标"。

---

## 六、不同模式的"充分"标准不同

Natural Depth 不是统一"写详细一点"，而是按模式判断充分标准：

| 模式 | 充分标准 |
|---|---|
| 内容 | 用户得到足够内容价值或观点。不需要商品决策闭环。 |
| 种草 | 用户建立兴趣 + 理解 + 偏好。不要求解决所有购买异议。 |
| 卖货 | 用户获得产品选择理由 + 信任依据 + 关键决策信息。不一定强 CTA，但不能只留下好感。 |

---

## 七、IP 模式必须保留 IP Asset

Anti-Patternization 可以删除"我判断……""我的标准是……"这种固定句型，**但不能删除人物资产本身**。

每篇 IP 内容最终至少沉淀一种：

- 判断方式
- 选择逻辑
- 审美
- 取舍
- 原则
- 对用户的态度
- 方法
- 专业边界

**检查：删除产品名称以后，还能不能感受到这个人是怎么做选择的？** 完全不能 → IP 过弱。

---

## 七·一、Narrative Detail Boundary（叙事细节权限）

已知事实可以自然表达，但**不得为了真人感自动补充"事情具体怎么发生"的细节**。

| 已知事实 | 可以写 | 禁止（除非 IP Fact Source 明确提供） |
|---|---|---|
| 对泡过几百款产品后选中 | 我们前后对泡过几百款。 | 店里摆满一排样品 / 左一杯右一杯 / 喝到舌头麻 / 熬到凌晨 / 连续试了几天 / 某个人当时说了什么 |

这些属于 **Narrative Detail Expansion**，必须和产品 Fact Expansion 一样受约束。

**原则：可以把真实经历说自然，不能给真实经历加戏。**

检查（每句涉及 IP 经历的内容问）：
- 这个细节是"**把已知经历说自然**"，还是"**给已知经历新增了具体发生过程**"？
- 新增的细节（场景布置 / 人物对话 / 时间长度 / 身体反应 / 顺序）是否有 IP Fact Source？
- 找不到来源的叙事细节 → **删除**，只保留已知经历本身。

与 Expression Authority 的关系：产品 Fact Expansion 受 `expression-authority.md` 约束；Narrative Detail Expansion 受本层约束。**两者同等严格。** 真人感来自"把真实经历说自然"，不来自"给真实经历加戏"。

---

## 八、Product Relevance Check（产品相关性检查）

尤其 IP 卖货：不能只讲一篇通用品类知识，最后顺手提一下产品。**必须至少有一个关键判断落到"为什么是当前 SKU"。**

例如不能只说"我看乌龙茶会看香落不落水"，还需要让用户自然知道"当前这款为什么通过了这个 IP 自己的筛选"。

---

## 九、字数采用 Soft Range

用户说"每版 300 字左右"，**不得解释为"必须 295—305 字"，但也不能解释为"越短越自然"**。

默认理解为合理软区间。例如短视频可根据内容自然落在**约 220—330 字**，具体由以下因素决定：

- Angle Complexity（角度复杂度）
- Mode Completion（模式完成度）
- Platform（平台）
- First Goal（第一目标）

**原则：Natural Completion ≠ Minimal Length。**

- 如果 240 字已经充分：停止。
- 如果 180 字导致 IP、SKU 理由或卖货决策不足：继续写。

---

## 十、Depth Budget（深度预算）

每个角度写之前内部判断：当前角度需要什么深度。

| 层 | 数量 |
|---|---|
| Core Claim（核心命题） | 1 个 |
| Core Proof（核心证据） | 1—2 个 |
| IP / User Decision Layer（IP 或用户决策层） | 根据当前模式增加必要的一层 |

**禁止：卖点百科。** 也**禁止：只有一个结论，没有足够支撑。**

即：**不过度展开，也不过度压缩。** 一个角度，一个核心命题；一个核心命题，讲到足够。不是"一个角度，讲完整个产品"。

---

## 十一、动作可以代替解释，但不能代替逻辑

特别是抖音、视频号：如果能通过画面证明（茶块形态 / 汤色 / 叶底 / 拆纸 / 冲泡 / 香气动作），**优先让镜头承担信息**。

但：**不能因为"镜头有动作"，就省掉用户必须理解的决策逻辑。**

**原则：画面负责证明，语言负责判断和意义。**

---

## 十二、Natural Ending 必须通过 Completion Gate

可以没有正式结尾。但结束前必须检查：

| 检查项 | 问题 |
|---|---|
| First Goal | 完成了吗？ |
| Mode | 没有漂移吗？ |
| IP Asset | IP 模式下形成了吗？ |
| Product Relevance | 商业任务里 SKU 选择理由存在吗？ |

**没有通过，不能结束。**

**句末强化句检查（Sentence-End Amplification Check）**：一个观点已经成立后，禁止为了力度追加"骗不了人 / 一喝就知道 / 比我说一百句都管用 / 好不好自己说了算"等句末强化句。删除最后一个强化句，如果观点已完整成立，优先删除（完整规则见 `anti-patternization.md` 十·一节）。

---

## 十三、最终最高原则

> **先找对值得讲的事情，再把这件事情自然讲够。**
> 而不是：**先决定写五篇，再想办法填满五个模板。**

一句话概括本层目标：

> **每一版都讲一个事情，但把这个事情真正讲够。**

## 与相邻 reference 的边界

- `dynamic-angle-discovery.md` 管**讲什么**（Angle Discovery / Angle Scoring / Semantic Distance / IP Asset 绑定 / Angle-Specific Mode Completion）；本文件管**讲到什么程度**。两者必须串联：先发现角度并绑定 IP Asset，再判断深度，再为每个角度设计独立成交路径。
- `anti-patternization.md` 管**规则不可见**（Natural Completion / Natural Ending / Rule Visibility / Sentence-End Amplification Check）；本文件补充"自然不等于短、留白不等于任务没做完、Mode Completion 优先于 Anti-Patternization、Narrative Detail Boundary"。Anti-Patternization 的 Natural Completion 在本文件升级为 Soft Range + Depth Budget。
- `final-output.md` 管**成品真人感与平台原生层**（信息减法/过度完整检测/自然连贯检测）；本文件补充"信息减法不能减到模式目标消失"，信息减法层与本文件的 Depth Budget 共同决定"减到什么程度"。
- `expression-authority.md` 管**事实边界**（产品 Fact Expansion）；本文件不新增产品事实，只决定"已有事实讲到什么程度"，并补充"IP 经历叙事细节"同样受边界约束（Narrative Detail Boundary）。
- `platforms.md` 定义平台规律与中心思想（Canonical Core）；本文件只要求"平台决定深度"，**不修改平台中心思想**。
